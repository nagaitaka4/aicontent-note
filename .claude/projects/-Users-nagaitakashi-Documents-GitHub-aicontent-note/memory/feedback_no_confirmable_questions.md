ファイル・記事・issue等で確認できることをユーザーに聞かない。先に自分で確認する。

**Why:** ユーザーは毎回CCへの説明コストがかかることを強く嫌がっている。記事の内容・記事のステータス・投稿済みかどうか・シリーズの流れなど、ファイルを読めば分かることは読んでから動く。

**How to apply:**
- 記事の内容を聞く前に記事ファイルをReadする
- 投稿状況を聞く前にposts-stock.mdを確認する
- シリーズの流れや結論を聞く前に該当記事のH2一覧・末尾をgrepする
- 「〜ということで合っていますか？」という確認もファイルで答えが出るなら不要
- 質問するのは「ユーザーの意図・好み・体験」のみ。事実確認はファイルで行う
