## 構成（H1・H2・H3の骨格）

```markdown
# テンプレートとは？AI業務で再現性を作る設計の考え方

<!-- GEO対応：H2より前に直接回答を配置 -->
テンプレートとは、同じ品質・同じ手順で仕事を再現するための「型」です。
AIに毎回ゼロから指示を書き直す手間をなくし、誰が指示しても・何度指示しても
同じ水準の結果に近づけるための設計です。

## テンプレートとは何か。「型」という言葉の実務的な意味
→ テンプレートの定義：同じ作業を繰り返すときに使う「型」
→ 雛形・フォーマットという一般的なイメージと、AI業務での意味の違いを整理
→ なぜ今、AIと仕事をする文脈でテンプレートが重要になっているか

## なぜAI業務でテンプレートが再現性を生むのか
→ AIは指示された通りに動く。指示が毎回違えば、出てくる品質も毎回変わる
→ テンプレートがあることで「誰が指示しても・何度指示しても」同じ品質に近づく
→ 実務での使い方：このブログの記事構成案フォーマット運用を具体例として説明
→ 内部リンク：プロンプトとは？AIに仕事を依頼する設計書の考え方（prompt-design-basics）
　　テンプレートとプロンプトの違いを補足

## テンプレートに含めるべき要素
→ 何を型にするか：構成の骨格・チェック項目・NGルール・完了条件など
→ 「毎回考え直している部分」を洗い出すのがテンプレート化の第一歩
→ 全部を型にしない。判断が必要な部分は残す（テンプレートは思考停止の道具ではない）

## テンプレートはAIに作ってもらえる
→ README.mdと同じく、テンプレートも自分でゼロから書く必要はない
→ 「この作業、毎回同じ手順を繰り返している」とAIに伝えれば、AIが型として整理してくれる
→ 実務体験：このメディアの構成案フォーマットも、やり取りの中でCCが整理して型になった経緯
→ 内部リンク：ディレクトリ構造とは？AI業務が整理されるフォルダ設計の考え方（directory-structure-basics）
　　テンプレートをどこに保存し、どう管理するかの軽い接続

## テンプレートとREADME・ルールファイルの役割分担
→ README.mdは「前提を共有するもの」、テンプレートは「作業を再現するもの」
→ 内部リンク：READMEとは？AIと人間が共有する業務マニュアルの作り方（readme-basics）
　　役割の違いを対比で説明
→ 両方があることで「何を・どうやるか」がAIにも人にも明確になる

## テンプレートは固定せず、育てていくもの
→ 完璧なテンプレートを最初から作る必要はない。運用しながら直していくもの
→ 「型を疑わず使い続ける」ことのリスク（状況が変わってもテンプレートが更新されない）
→ このメディアの最重要思想「完璧より継続」との接続
→ 次回予告：ルールファイル（R-09）へつなげる
```
