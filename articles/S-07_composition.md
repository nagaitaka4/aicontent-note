# S-07 構成案
## ブログの内部リンクの貼り方とSEO効果の出し方

**メインKW**：内部リンク 貼り方 SEO
**検索意図**：情報収集＋ハウツー実践（「どう貼ればいいか」を知りたい層）
**カテゴリ**：AIとコンテンツの実務
**スラッグ候補**：internal-link-guide
**想定文字数**：3,000〜3,500字（ハウツー系）
**インタビュー**：不要（SEO実務系・CC先導）

## 重複確認

`grep -rli "内部リンク" articles/` で確認済み。内部リンクをメインテーマにした記事は存在せず、重複なし。近いテーマの `ai-article-structure-h1`（H1/H2/H3の構成論）とは切り口が異なる（構成＝見出し設計、本記事＝記事間のつなぎ方）ため、差別化して展開する。

## 構成（H1・H2・H3の骨格）

```markdown
# ブログの内部リンクの貼り方とSEO効果の出し方

<!-- GEO対応：H2より前に直接回答を配置 -->
内部リンクとは、同じサイト内の記事同士をリンクでつなぐことです。
関連記事へ自然に誘導することで、検索エンジンのクロール性と読者の回遊率の両方を高められます。

## 内部リンクとは何か。外部リンクとの違い
→ 内部リンクの定義（同一サイト内の記事同士をつなぐリンク）
→ 外部リンクとの違い（サイトの評価が外に流れるか・内にとどまるか）
→ SEOで重視される理由：クロール性・関連性の伝達・回遊率

## 内部リンクを貼るタイミングは3つある
→ 新記事を公開したとき（過去記事から新記事へ・新記事から過去記事へ、双方向にリンクを足す）
→ 関連記事が一定数たまったとき（シリーズ・カテゴリー単位でまとめて整備）
→ 既存記事をリライトするとき（見直しのたびにリンクも更新する）

## 内部リンクの正しい貼り方
→ アンカーテキストは記事内容を自然に表す文言を基本にする（記事タイトルをそのまま使うとは限らない。「こちら」等の不自然な言い換えは避ける）
→ リンクを置く位置（本文中の関連箇所／末尾の関連記事リスト）
→ 本数は「多いか少ないか」ではなく関連性で決める。関連性が薄いリンクを本数合わせで足さない
→ 内部リンク：AIに記事構成を任せてわかった。本当に重要なのはH2ではなくH1（ai-article-structure-h1）

## このメディアで実際にやっている内部リンク設計
→ 公開記事が増えるたびにどうつないでいるか。カテゴリー・シリーズ単位での設計方針
→ 外注・代行系の記事への導線をどう作っているか
→ 内部リンク：ブログ更新が止まる理由と、外注を検討するタイミングの見極め方（blog-update-outsource-timing）

<!-- 途中CTA（実例セクションの直後） -->

## やりがちな内部リンクの失敗
→ 関連性の薄い記事へのリンク
→ リンクを貼りすぎて逆に読みにくくなる
→ アンカーテキストが不自然（「詳しくはこちら」の多用など）

## 内部リンクを見直すタイミングとチェック方法
→ 定期的な棚卸し（リンク切れ・重複チェック）
→ サーチコンソールの「リンク」レポートで確認できること（内部リンクが少なく孤立しているページ・逆に集中しすぎているページの発見）
→ クリック数そのものは直接見えないため、整備後の変化は検索パフォーマンス（掲載順位・インデックス状況）で間接的に確認する
→ 確認して終わりにせず、リンクが少ないページに関連記事からのリンクを足す改善サイクルにする
→ 内部リンク：SWELLのSEO設定｜最初にやるべき項目を優先順位つきでまとめてみた（swell-seo-settings）

## 内部リンクは一度で完成させなくていい
→ 最初から完璧な設計をしなくていい。記事が増えるたびに育てるもの
→ 「止めずに回す」運用の中で内部リンクも更新し続ける、という位置づけ
→ 内部リンクを整備すること自体が、これまで書いた記事を資産として育てる作業になる

<!-- 末尾CTA -->
```
