# S-22 構成案

**タイトル：** AIでブログ構成を安定させる運用フロー｜ルールファイルから確認プロセスまで

**スラッグ候補：** ai-blog-structure-operation-flow / ai-composition-operation-flow

---

## 構成全体の設計意図

このメディアの最重要思想は「完璧より継続」。その思想を具体的に**実装**する仕組みを示す記事。

**インタビュー素材から導き出した軸：**
ユーザーが実際に毎回やっているフロー（ネタストック→優先順位→CC構成案→カスタムGPT確認→最終チェック）を言語化し、その中に仕込まれた「60点構成の考え方」「ルールファイルの役割」「人間が決めるべき部分」を、体験ベースで読者に伝える記事。

**S-09との棲み分け：**
- S-09は「なぜH1/H2/H3をこう設計するのか」という**理論・基礎**
- S-22は「その構成をどう毎回安定して作り、どう育てるか」という**実装・運用**

**対象読者の問い：**
「S-09を読んだけど、実際に毎回この品質で構成を作るにはどうするの？」「ルールファイルって何？」「何が『60点』なの？」

**この記事で理解させること：**
1. 毎回同じフロー（5ステップ）を回すことで安定を実現する
2. 「60点構成で始める」「育てながら進める」という考え方の正体
3. ルールファイル（CLAUDE.md等）がAIとの協働を安定させる装置であること
4. 人間が決めるべき部分（H1/H2/H3の優先順位）と、AIに任せる部分の区別

## 構成（H1・H2のみ）

```markdown
# AIでブログ構成を安定させる運用フロー｜ルールファイルから確認プロセスまで

## S-09との違い。この記事は「理論」ではなく「運用」を扱う
→ 目的：S-09で「構成の設計方法」を学んだ読者が、「では毎回どうやるのか」という疑問に答える
→ 構成の意図：導入として、この記事の位置づけと読む価値を明確にする

## ブログ構成を毎回安定して作るための5つのステップ（全体フロー）
→ 目的：5つのステップの全体像を先に見せることで、以降の詳細説明の文脈を作る
→ 構成の意図：「フロー全体を理解してから、各ステップに進む」という読者体験の設計
→ 記載内容：ネタストック → 優先順位 → CC構成案作成 → カスタムGPT確認 → 最終チェック

## ステップ1：ネタ候補から優先順位を決める
→ 目的：「何を書くか」の判断基準を示す
→ 構成の意図：フロー最初のステップ。ここでメディア軸と読者ニーズが反映される
→ 記載内容：article-backlog.mdの実態 / 「素材がある」ではなく「メディアに今足りない」で判断する考え方

## ステップ2：CC に構成案を作成してもらう
→ 目的：「構成案作成」というAI活用の具体場面を実装レベルで説明
→ 構成の意図：ステップ2。ここで「人間の判断」と「AIの能力」が最初に接触する場面
→ 記載内容：構成依頼前に「記事の軸」を言語化する / 「60点構成」という概念 / コードブロック形式の構成

## ステップ3：カスタムGPT で構成を確認する
→ 目的：「AIに確認させる」というフローの位置づけと具体方法
→ 構成の意図：ステップ3。人間の判断（S2で言語化）をAIに「検証」させる段階
→ 記載内容：ルールファイルをカスタムGPTに食わせる / 「この構成でいいか」を問う方法 / 修正の判断軸

## ステップ4：ルールファイルで最終チェック
→ 目的：「ルールファイル」が何であり、なぜ必要か、を実装場面から理解させる
→ 構成の意図：ステップ4。構成が「記事のルール」に沿っているか、人間が確認する段階
→ 記載内容：チェック項目 / CLAUDE.mdとの連携 / 「ここからは執筆」という分岐点

## ステップ5：執筆前に「体験情報」を整理する
→ 目的：「構成案」と「執筆」の間に何が必要か、を示す
→ 構成の意図：ステップ5。体験型記事では、AIが知らない背景情報がある。それをここで渡す
→ 記載内容：「自分がやった体験」をCCが知らないと構成がズレる / 情報を渡すタイミング / 社内用語や独自工程の共有

## 「60点構成」とは何か、そしてなぜそれで十分なのか
→ 目的：「完璧な構成を最初から作る」という誤解を解く
→ 構成の意図：運用フロー全体を通じて最重要な概念。これを理解しないと「構成に時間がかかりすぎる」という陥穽に落ちる
→ 記載内容：「60点構成の危険性」（公開する構成ではなく、案作成時の話） / 「育てる」という実装パターン / ルールファイル更新のサイクル

## H1・H2・H3 の優先順位は人間が決める
→ 目的：「AI任せにしてはいけない判断」を明示する。AIとの役割分担を言語化
→ 構成の意図：読者に「自分たちの判断」の重要性を自覚させる段階
→ 記載内容：メディア軸・読者ニーズ・導線を踏まえた順序付け / 自分たちメディアの「型」を把握する / H3階層化も同じロジック

## ルールファイルは「育てる」仕組み
→ 目的：「ルールとは何か」をこのメディアの実態から理解させる
→ 構成の意図：全体の最後。フロー全体を支える「基盤」について説明
→ 記載内容：「完璧なルールを最初から作る」のではなく、運用しながら育てる / CLAUDE.md追記の実態 / 「ルール更新 → 次の記事に反映」のサイクル
```

## H2順序の設計理由

**フロー全体を理解する → 背景にある考え方を学ぶ**

1. **導入**（H2①）：S-09との関係性を明確化
2. **全体フロー**（H2②）：5ステップを俯瞰。読者の予習
3. **5ステップの詳細**（H2③〜⑦）：実装順序で説明。How を理解
4. **運用の考え方**（H2⑧⑨⑩）：60点構成・優先順位・ルール育成。Why を学ぶ

この順序で「完璧より継続」という最重要思想を、読者の体験を通じて理解させる。
