# なぜAI活用は情報整理が9割なのか。成果はAIに渡す前に決まる

AI活用の成果を大きく左右するのは、渡す情報がどれだけ整理されているかです。プロンプトの書き方だけでなく、渡すものが揃っているかどうかでも、出力は大きく変わります。

前回の[ルールファイル](https://aicontent-note.com/rule-file-basics/)まで9本続いたこのシリーズが、なぜすべて情報整理の話だったのかを振り返ります。

---

## AIの出力は、渡した情報の範囲でしか良くならない

AIは、渡されていない前提を知りません。ここが出発点です。理由は3つあります。

・渡していない前提は、AIには見えない<br>
・説明が欠けた部分は、その場の判断で埋められる<br>
・モデルが新しくなっても、渡す情報が整理されていなければ、その性能を十分に活かせない

3つ目が、いちばん実感しにくいところだと思います。新しいモデルが出るたびに期待しますが、手元の資料が散らかったままだと、返ってくるものはあまり変わりません。渡すものが同じなら、返ってくるものも似た範囲に収まります。

もちろん、新しいモデルで解決することもあります。ただ、原因が渡す情報の側にあるなら、そこを整えないと変わりません。

【ポイント】<br>
渡していない情報は、どんなモデルでも読めません。

---

## 「プロンプトが下手だから」ではない

思ったような答えが返ってこないと、指示の書き方を疑いたくなります。ただ、原因がそこにないことは多いです。

【はてな】<br>
答えが浅いとき、先に見るべきなのは指示の言い回しではなく渡した資料です。

前提を書いた資料を添えたときと、口頭の一言だけを渡したときでは、返ってくるものが別物になります。書き方を何度も直すより、渡すものを足したほうが早く届きます。

とはいえ、指示の設計が要らないわけではありません。[プロンプト](https://aicontent-note.com/prompt-design-basics/)と[コンテキスト](https://aicontent-note.com/context-design-basics/)は、どちらも必要です。ただ、指示だけを磨いても、前提になる情報が足りなければ出力は安定しません。

【メモ】<br>
指示を磨いても変わらないときは、渡しているものを見直します。

---

## 情報が散らかったままだと、何が起きるか

AI活用がうまく回らないとき、症状にはいくつか決まった形があります。まず、自分がどれに当てはまるかを見てみます。

| 起きていること | 整理面で考えられる原因 |
|---|---|
| 毎回同じ説明を繰り返している | 判断基準がファイルになっていない |
| 長い会話の後半で指示がズレる | 渡す情報を選べていない |
| AIが必要なファイルを見つけられない | 情報の置き場所が決まっていない |
| 渡した資料をうまく読んでくれない | 構造のない形式で渡している |

こうした症状の多くは、AIの性能だけでなく、情報整理の不足からも起きます。

逆に、渡すものが揃っていると、同じ説明を繰り返す回数を減らせます。前提を共有し直す手間が減るぶん、本題の作業に時間を回せます。

## シリーズで扱った9つの概念は、すべて情報整理の話だった

9本の記事は、それぞれ別のテーマを扱っているように見えます。並べてみると、共通しているものが見えてきます。

| 概念 | 整理しているもの |
|---|---|
| [プロンプト](https://aicontent-note.com/prompt-design-basics/) | 依頼内容 |
| [コンテキスト](https://aicontent-note.com/context-design-basics/) | AIが参照する情報の範囲 |
| [トークン](https://aicontent-note.com/token-design-basics/) | 渡す情報量と優先順位 |
| [Markdown](https://aicontent-note.com/markdown-basics/) | 情報の構造 |
| [ディレクトリ構造](https://aicontent-note.com/directory-structure-basics/) | 情報の置き場所 |
| [Git](https://aicontent-note.com/git-basics/) | 情報の変更履歴 |
| [README](https://aicontent-note.com/readme-basics/) | 業務の前提 |
| [テンプレート](https://aicontent-note.com/template-basics/) | 繰り返す作業の型 |
| [ルールファイル](https://aicontent-note.com/rule-file-basics/) | 判断基準 |

9本とも、何かしらの情報を整理する話でした。別々の技術を順に解説していたのではなく、同じ1つの問いに角度を変えて答えてきたことになります。

伏線は、第3回のトークンの回に置いていました。あの記事の結びに「必要なものを選んで渡す設計」と書いています。あれは1記事分の結論のつもりでしたが、実際にはシリーズ9本ぶんの答えでした。

---

## 整理する対象は、頭の中ではなくAIと共有するファイル

情報整理と聞くと、頭の中を整理する話に見えるかもしれません。AI活用の場合は、対象が少し違います。

【インフォ】<br>
整えるのは、AIと自分が同じものを見られる形にした情報です。このシリーズでは、それを主にファイルとして残してきました。

頭の中で分かっていても、共有できる形になっていなければAIには届きません。手が動く場所に置いて初めて、整理したことになります。

この形にすると、AIのためだけの作業ではなくなります。同じファイルは人も読めるので、別の担当者が引き継いでも同じ基準で動けます。

【ポイント】<br>
同じファイルをAIも人も読めることが、整理のいちばんの利点です。

ここまでの9本で扱ってきたのは、AIの操作方法ではなく、渡すものをどう整えるかでした。実際の運用の形は「[AIでブログ構成を毎回安定させる方法。実際の運用フローを公開](https://aicontent-note.com/ai-composition-operation-flow/)」にまとめています。

整えた結果が形になって残ったものを、次回は「環境」として扱います。
