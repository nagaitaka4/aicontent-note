# ブログ記事の構成の作り方｜H1・H2・H3見出し設計を実例で解説

ブログ記事の構成は、H1・H2・H3という3階層の見出しで設計します。H1は記事全体のテーマを示す1本の見出し。H2は読者の「次に知りたいこと」を並べた大見出し。H3はH2の内容をさらに細分化したいときに使う小見出しです。

この3つを設計することが「記事の構成を作る」ということで、SEO・読みやすさ・AIとの制作効率、いずれにも直結します。

このノートでは、H1/H2/H3それぞれの役割・SEO上の設計ポイント・実際のこのブログの記事を使った実例を整理します。

---

## H1・H2・H3とは何か。3つの役割を整理する

まず定義から整理します。H1・H2・H3は、HTMLの見出し要素（Heading）のことです。数字が大きくなるほど階層が下がり、H1が最上位、H3がその下に位置します。

### H1：記事全体のテーマを示す。1記事に1本だけ

H1はページの「表札」のようなものです。この記事が何について書かれているかを1行で示します。

1ページに1本だけ存在するのが原則で、記事タイトルとH1を一致させるのが基本的な設計です。WordPressで記事タイトルを入力すると自動的にH1として設定される構造になっているため、意識しなくてもH1は1本になっていることがほとんどです。

### H2：読者の「次に知りたいこと」を順番に並べる

H2は記事を大きなブロックに分ける見出しです。「この記事で何を扱うか」の目次になります。

H2だけを順番に読んだとき、記事の全体像が伝わるのが理想です。「H2①を読んだら次はこれが気になる」という流れになっていれば、構成として機能しています。

### H3：H2の内容を細分化したいときに使う。なくても成立する

H3はH2の中をさらに分けたいときに使う見出しです。H2の内容が複数の視点・手順・事例で構成されるとき、それぞれにH3をつけることで読みやすくなります。

一方で、H3がなくてもH2単体で読める記事はたくさんあります。「とりあえずH3を入れる」は構造を複雑にするだけで、必要な場面に絞って使うのが原則です。

## SEOの観点でH1・H2・H3をどう設計するか

H1/H2/H3はSEOにも影響します。検索エンジンは記事の見出し構造から「何が書かれているか」を判断しており、設計次第で評価が変わります。

### H1設計：メインKWを前半に。35文字以内を目安に

H1（タイトル）には、その記事でターゲットとするメインキーワードを含めます。特に文字列の前半に配置することで、検索エンジンが認識しやすくなります。

文字数の目安は35文字以内です。Googleの検索結果に表示されるタイトルの文字数を意識したもので、これを超えると途中で省略表示されます。キーワードを詰め込むのではなく、読んで意味が通る日本語の中にキーワードが入っている状態が理想です。

### H2設計：検索意図の流れに沿って並べる。順番に意味を持たせる

H2の並び順には意味を持たせます。「この疑問を解決した読者が次に気になること」という流れで並べると、記事全体に一貫した設計が生まれます。

並び順がバラバラだと、読者が途中で「何の話だっけ？」となり離脱しやすくなります。H2の設計は、読者の思考の流れに沿っているかを確認しながら調整するのが基本です。

### H3設計：H2だけで説明しにくいときに使う

H3を使う判断基準は、「H2単体では説明が複雑になりすぎるとき」です。具体的には、比較項目が複数ある・手順を段階で分けたい・事例を個別に整理したい、といった場面です。

1つのH2の下に置くH3の数は2〜4本が目安で、それ以上になるならH2を分ける方向を先に検討します。

> 【ポイント】
> H3は「使ってもいいか」ではなく「なくても読めるか」を先に確認します。なくても読めるなら、H2のまま続けるのが構造をシンプルに保つ方法です。

## 実例：このブログの記事でH1〜H3がどう設計されているか

設計の考え方は説明できますが、実際の記事で見た方が使い分けの感覚は掴みやすいと思います。このブログの公開記事3本を、H1/H2/H3の構造で比較します。

### 実例①：比較型（H2中心・H3はほぼなし）

記事：[社内更新と外注、どちらが本当にコスパがいいのか](https://aicontent-note.com/in-house-vs-outsource-cost/)

| 項目 | 内容 |
|---|---|
| H1 | 社内更新と外注、どちらが本当にコスパがいいのか |
| H2 | ・「社内でやった方が安い」は見えているコストだけかもしれない / ・社内更新のコストを計算してみる / ・外注のコストを計算してみる / ・コスパは「料金」ではなく「継続」で決まる / ・社内更新が向いている会社・外注が向いている会社 |
| H3 | 「コスパは継続で決まる」の1セクションのみ3本 |
| 設計理由 | 比較記事はH2で話題を切り替えながら進める構造が合っている。コスト計算→比較→判断という流れをH2で担い、H3はひとつのH2にだけ絞った |

この記事のH2を読むだけで「社内vs外注を多角的に比較している記事」と伝わります。各H2が独立して完結する内容のため、H3を最小限にしても記事として成立しています。

### 実例②：体験型（H3で体験・手順を細分化）

記事：[コンテンツ運用が続かない理由と、止めないための仕組みの作り方](https://aicontent-note.com/content-operation-system/)

| 項目 | 内容 |
|---|---|
| H1 | コンテンツ運用が続かない理由と、止めないための仕組みの作り方 |
| H2 | ・自分が止まりかけた、正直な話 / ・「続かない」には、だいたい同じパターンがある / ・意志の問題だと思っていたけど、構造の問題だった / ・運用を止めないために変えた3つのこと / ・今の運用フローを、具体的に書いておきます |
| H3 | 複数のH2にそれぞれ2〜3本ずつ |
| 設計理由 | 体験型の記事はH2で大きな流れ（状況→原因→解決）を作り、H3で各体験の中の「細かい話」を整理する。「3つのパターンがある」「3つ変えた」という構造では、H3で各項目を分ける方が読者にとって親切 |

H2だけで「状況→原因→解決→実践→結論」という流れが見えますが、各H2の中身はH3がないと読みにくい構造です。H3が必要な典型的なパターンです。

### 実例③：概念解説型（H3フル活用）

記事：[Markdownとは？AI時代に全員が使うべき理由を実務視点で解説](https://aicontent-note.com/markdown-basics/)

| 項目 | 内容 |
|---|---|
| H1 | Markdownとは？AI時代に全員が使うべき理由を実務視点で解説 |
| H2 | ・Markdownとは：「記号で構造を表したプレーンテキスト」のこと / ・なぜAIはMarkdownを好むのか / ・実はMarkdownは身近な場所で使われている / ・Markdownは「AI時代の共通言語」になっている / ・Markdownを理解すると何が変わるか |
| H3 | ほぼすべてのH2に複数本 |
| 設計理由 | 概念解説型は「1つのH2に複数の観点が含まれる」構造になりやすい。「なぜAIはMarkdownを好むのか」の下に「構造がわかりやすい」「人間にも読める」「余計な装飾情報がない」などH3が並ぶ。H3がないとH2の中が長くなりすぎる |

3本を並べると、同じH1/H2/H3の仕組みでも記事の種別によって使い方が変わることがわかります。構成に「正解の型」はなく、その記事の内容に合わせて設計するものです。

## 構成の骨格を作る手順

H1/H2/H3の役割がわかったところで、実際の設計手順を整理します。

### よくある失敗：H3から作り始める

構成を作ろうとするとき、H3を埋めながら記事を設計してしまうことがあります。これは順番が逆です。

H3はH2の内容が決まって初めて必要かどうか判断できるもので、H3から設計を始めるとH2の設計がバラバラになります。「H3に入れたい内容があるから、それを収められるH2を後から作る」という状態になり、記事全体の流れが崩れます。

### まずH1（タイトル）を固める。KWと文字数を確認する

最初に決めるのはH1です。この記事で狙うキーワードは何か、それを35文字以内のタイトルで表現できるかを確認します。

H1が曖昧なまま設計を進めると、H2の選択がブレます。「この記事で何を扱うか」の核がH1なので、ここを固めることが構成設計のスタート地点です。

### H2を並べる。読者の「次に知りたいこと」の順に

H1が決まったら、H2を並べます。この記事を読む人が最初に知りたいこと・次に知りたいこと・最後に確認したいことの順番で並べるのが基本です。

H2の候補は多めに出してから絞るのが安全です。候補をすべて出したあとで「この順番で読むと自然か」を確認し、並び替えや統合をします。

### H3はH2を書き出してから判断する。最初から決めなくていい

H3を入れるかどうかは、H2の設計が終わってから判断します。

「このH2の内容、複数の観点で説明するな」と気づいたらH3を追加する、という判断の仕方です。最初からH3の数を決める必要はありません。

### 構成作成後のチェックポイント

構成ができたら、以下を確認してから執筆に入ります。

> 【チェック】
> ・H1は1本だけか
> ・H2だけを順番に読んで、記事の流れがわかるか
> ・H3は本当に必要な箇所だけか
> ・読者の疑問の順番に並んでいるか

この4つを満たしていれば、構成として機能しています。ここで確認しておくと、執筆段階で「やっぱり構成を直したい」となるケースを減らせます。
