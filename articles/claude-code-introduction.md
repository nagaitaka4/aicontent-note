# Claude Codeとは何か？できること・使い方を実際に使って解説する

Claude Codeが気になっているけど、

- 何をインストールすればいいのかわからない
- CLIやターミナルが難しそう
- 非エンジニアでも使えるのか不安

こう感じている人は多いと思います。
自分も完全に同じ状態からスタートしました。

この記事では、Claude Codeとは何か、実際に何ができるのか、
初心者の私がどうやって導入したのかを、リアルな体験ベースでまとめます。

[以前の記事](https://aicontent-note.com/ai-writing-claude-setup/)では
Claudeのプロジェクト機能に乗り換えた話を書きましたが、この記事はその続きにあたります。
「プロジェクト機能の次のステップ」として、Claude Codeに手を出した流れです。

---

## Claude Codeとは何か

### チャット版Claudeとの違い

ChatGPTやChaudeのチャットは、質問や指示を送ると「答えや提案を返してくれる」ツールです。
実際にファイルを作ったり、保存したり、更新したりはしてくれません。

Claude Codeは違います。
指示を出すと、PC上のファイルを直接操作してくれます。
ファイルを作る、書き換える、フォルダを整理する、といった作業を実際にやってくれます。

「AIが答えてくれる」から「AIが動いてくれる」に変わる、というイメージです。

導入時にターミナルという画面を使う場面がありますが、セットアップが終われば、
今のところ、日常の作業はほぼVS Codeで完結しています。
最初だけ乗り越えれば、あとはほとんど気にならなくなると思います。

### イメージで理解すると...

ひとことで言うと、**Claude Codeは、AIがPCを直接操作してくれる感覚**です。

チャットで「この記事を書いて」と指示すると記事を書くだけでなく、
「このフォルダの中にこのファイルを作って、この内容で書いて、保存して」という作業そのものをやってもらえます。

「AIが動いてくれる」というのは、チャット型のAIとは全く違う体験です。

---

## Claude Codeでできること

### 本来の主機能（コーディング・開発）

Claude Codeはもともとエンジニア向けのツールのようです。
プログラムやアプリのコードを書く・修正する・実行する、といった開発作業が本来の主機能にあたります。

ただ、使い始めてみると、コンテンツ制作・運用との相性がかなりいいことがわかってきました。  

### コンテンツ制作・運用で使えること

非エンジニアでも使える領域はここが中心です。

- 記事・資料・ドキュメントの作成・編集
- ファイルの作成・整理・移動・削除
- フォルダ構成の設計・構築
- 作業ログ・メモのファイルへの記録・保存
- 画像のリネームやトリミングなど簡単な画像処理
- GitHub連携（変更履歴管理・Issue管理）

「作業そのものを任せられる」というのが、チャット型のAIとの一番の違いです。

### 外部ツールと組み合わせると広がること

Claude CodeはAPIと呼ばれる仕組みを使って、外部のサービスと連携することができます。

たとえばAdobe FireflyにはAPIが公開されていて、
Claude CodeからそのAPIを呼び出すように設定すれば、以下のような自動化が可能になります。

- Claude Codeに「アイキャッチ画像を作って」と指示する
- Claude CodeがFirefly APIを呼び出す
- 画像が自動生成されてフォルダに保存される

人間が手動でコピー＆ペーストする手間がなくなる、ということです。

ただしこれはAPIの設定が必要な上級の使い方で、すぐにできるものでは今のところないみたいです。
自分の現状は、Claude Codeに画像生成用のプロンプトを考えてもらい、それをFireflyに貼り付けて生成するやり方です。
自動化はまだ今後の課題です。

使いこなすほど自動化できる範囲が広がる、というのがClaude Codeの本質的な強みだと感じています。

Claude Codeがいいとは聞いていましたが、何をどの順番でインストールすればいいのか、最初は全くわかりませんでした。

まずYouTubeで動画を検索して、以下の3本を参考にさせてもらいました。

- [【AI活用に大活躍】非エンジニアのためのGit+GitHub入門【コマンド暗記不要です/GitHub Desktop】](https://www.youtube.com/watch?v=Uml3jEPWIKo)

そもそも、エラーなのかどうかすら判断できない場面が思ったよりも多かったです。

## 実際に導入した流れ

### インストールしたツール一覧

最終的にインストールしたのは以下のものです。

| ツール | 用途 |
|---|---|
| Visual Studio Code | メインの作業環境 |
| GitHub Desktop | GitHubの操作をGUIで行うアプリ |
| Warp | ターミナルアプリ |
| Node.js | Claude Codeの動作に必要な実行環境 |

Node.jsはWarpのターミナルを使ってインストールしました。
他にも「言われるがままインストールしたもの」はいくつかあります。
正直、何を入れたか全部は覚えていません（笑）ただ、セットアップの流れで求められたもの、AIに「入れたほうがいい」と言われたものをそのまま入れた形です。この用途で必要とされるものは、基本的に入れて問題ないと思っています。あくまで自己判断ですが。

### 全部英語で、何が起きているかわからなかった

CLIの概念は動画でなんとなく理解できました。
ただ、実際のターミナル画面で入力して進めると、何が起きているのかが全く読めませんでした。

エラーが出ているのか、正常に進んでいるのか。
「つまずいているのかどうか」すら判断できない状態が続きました。

そこで、ClaudeとChatGPTに画面をそのまま見せながら逐一確認するやり方で進めました。
「この画面は正常ですか？」という聞き方でも答えてくれたし、
途中からはただスクショを貼っただけで解決策を返してくれました。

知識がなくても、AIに見せながら1つずつ進めれば通過できます。

### ターミナルとVS Codeの感覚の違い

Warpのターミナルは、今も慣れているとは言えません。
概念は理解できても、コマンドを打つ操作感がまだ遠い感じがあります。

一方、VS Code（Visual Studio Code）はFinderに近い操作感で作業ができます。
左側にフォルダ構造が見えて、ファイルをクリックして開いて編集する。
その感覚が直感的で、最初から使いやすかったです。

今は作業のほとんどをVS Codeで完結させています。
ターミナルを使う場面は、導入時と比べてほとんどありません。

## GitHubとの連携

GitHubは、ファイルをクラウド上で管理できるサービスです。
「いつ・何を・どう変えたか」の履歴が自動で残り、間違えた時点まで戻せます。
Googleドライブに近いイメージですが、変更履歴の管理に特化しています。

### なぜGitHubと連携するのか

Claude Codeは、特定のフォルダを作業の単位として動きます。
ローカルのフォルダだけでも使えますが、変更履歴の管理やバックアップを考えると、GitHubと連携しておくのが現実的です。
操作自体はGitHub Desktopを使えば、コマンドなしでボタン操作で進められます。

### commitとSync Changesの意味

GitHubを使い始めると最初に混乱するのがこの2つです。

- **commit**：変更内容をローカル（自分のPC）に記録するスナップショット
- **Sync Changes（Push）**：commitした内容をGitHubのクラウドにアップロード

ローカル保存 → クラウド保存、という2段階の流れです。
最初はなぜ2段階なのかわかりませんでしたが、
「間違えたときに特定の時点まで戻せる記録」として機能しているのだなぐらいの理解で十分だと思います。

### Claude CodeとGitHubを連携するとできること

GitHub連携によって使えるようになる主なものをまとめます。

- 変更履歴が自動で残る（いつ・何を変えたかがすべて記録される）
- 間違えた変更をcommit時点に戻せる（ロールバック）
- 複数ファイルをまとめて一元管理できる
- GitHubのIssueへの書き込みやクローズもClaude Code経由で実行できる

このメディア自体も、記事ファイルや運用ルールのmdファイルをすべてGitHubで管理しています。
運用を止めないための仕組みについては[こちらの記事](https://aicontent-note.com/content-operation-system/)で書いています。

## mdファイルを読み込ませてClaude Codeを育てる

Claude Codeの特徴のひとつが、mdファイルを「記憶」として持てる点です。

メディアのルール・記事の書き方・ワークフロー・過去記事などをmdファイルとして作成しておき、
Claude Codeに読み込ませると、毎回説明しなくてもその内容を前提として動いてくれます。

### 使うほど精度が上がる仕組み

チャット版Claudeのプロジェクト機能と発想は近いですが、
Claude Codeの場合はファイルの更新・作成・蓄積もClaude Code自身が行ってくれます。

作業を重ねるほどmdファイルが充実していき、指示の精度が上がっていく感覚があります。
「環境が資産になる」という表現が一番近いかもしれません。

具体的にClaude Codeに任せているのは、以下のようなことです。

- ワークフローや運用ルールのmdファイルの更新
- リサーチメモや作業ログのファイルへの記録・保存
- フォルダ構成の設計・構築

---

## 実際に何が変わったか

### 作業面での変化

- 記事制作のスピードが上がった
- ファイル管理が圧倒的に楽になった
- 「あの情報どこに書いたっけ」がなくなった
- 画像処理やフォルダ整理など、細かい作業をClaude Codeに任せられるようになった

以前はファイルの整理やメモの管理に思ったより時間を使っていました。
Claude Codeに任せるようになってから、その手間がほぼなくなっています。

### 所感

使い始めてから、「これが使えるかどうかで仕事の質と量に差が出てくる」という感覚が強くなっています。

Claude Codeが当たり前になった先では、
AIにできない部分——職人的な技術、コミュニケーション、判断力——がより重要になっていく気がしています。
AIが作業を肩代わりするからこそ、人がやるべき部分の価値が上がっていく。

正直、まだ全然使いこなせていないし、できることの全体像も見えていません。
それでも可能性の大きさははっきり感じていて、ワクワクしながら、同時に少し焦っています。

---

## まとめ・Claude Codeは使うべきか

- Claude Codeは「作業そのものを任せるAI」。チャット型とは別物
- 非エンジニアでも導入できる。ただし最初は時間がかかる
- GitHubとセットで理解すると、できることが一気に広がる
- mdファイルを育てるほど、作業環境が資産になっていく

触らないと実感できない部分が多いので、まずは小さく使ってみるのが一番だと思っています。
