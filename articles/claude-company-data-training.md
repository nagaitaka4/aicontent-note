# Claudeに会社の情報を渡して大丈夫か。データが学習に使われる条件

Claudeでは、==通常のチャットが学習に使われるかは設定で変わります==。
前半は学習に使われる条件、後半は渡してしまったときの対処です。
私はこの設定に気づかず、オンのまま取引先名や領収書を入れていました。

## Claudeのチャットが学習に使われるかは、プランと設定で決まる

==答えは、Claudeのプランと、モデル改善の設定で決まります==。
まずは、学習に使われる条件だけを見ます。
公式の条件を先に表にします。

| Claudeのプラン | 学習に使われるか | 標準の保持期間 | 根拠 |
|---|---|---|---|
| Free・Pro・Max＋設定オン | 使われる | 5年 | [Claude Code公式 Data usage](https://code.claude.com/docs/en/data-usage) |
| Free・Pro・Max＋設定オフ | 使われない | 30日 | 同上 |
| Team・Enterprise・API | 既定で使わない | 30日 | 同上・[料金ページ](https://claude.com/pricing) |

※そのアカウントでClaude Codeを使った分も、同じ扱いです。
※安全性レビュー対象の会話や、自分から送ったフィードバックには、別の保持期間が適用される場合があります。
※Claude.aiのIncognitoチャットは例外で、設定がオンでも学習には使われません（[プライバシーセンター](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)）。

公式の原文は「when this setting is on」、つまり設定がオンのときに使う、です。
**「Claudeだから危ない」でも「有料だから安全」でもなく、どの設定で使っているかで答えが変わります**。

### この記事で言う「渡す」とは

**チャットに打ち込んだ文も、貼り付けた文も、添付したファイルも同じ扱い**です。
==公式は対象を「会話のまとまりと、その中身すべて」と説明==しています。

・チャットに打ち込む / 貼り付ける → 対象<br>
・ファイルを添付する → 対象<br>
・Claude Codeにファイルを読ませる → 対象（コーディングセッションとして扱われる）<br>
・Google DriveなどのコネクタやMCPサーバーの中身 → **対象外**。ただし会話に直接コピーした分は対象

最後の1つだけ、扱いが違います。
つなげたサービスの中身そのものは学習に使われませんが、本文に貼れば会話の一部になります（[プライバシーセンター](https://privacy.claude.com/en/articles/10023580-is-my-data-used-for-model-training)）。

ただし、**学習に使われない設定なら何でも入力してよい、という意味ではありません**。
Anthropicの[Consumer Terms](https://www.anthropic.com/legal/consumer-terms)は、入力する情報の権利や許可を利用者側に求めています。
原文では「all rights, licenses, and permissions」を持つと利用者が保証します。

【ポイント】<br>
**有料のPro・Maxでも、設定がオンなら学習に使われる**

---

## オンかオフか、どこで確かめるか

**設定の場所は、「設定」 → 「プライバシー」**です。
見るだけなら、1分かかりません。

1. Claudeの画面で、自分の名前を押す<br>
2. 設定 → プライバシーの順に開く<br>
3. ==AIモデルの改善に協力する==のスイッチを見る

URLで直接開くなら、[claude.ai/settings/data-privacy-controls](https://claude.ai/settings/data-privacy-controls)です。
英語表示での名前は「Help Improve our AI models」です（[プライバシーセンターの手順](https://privacy.claude.com/en/articles/12109829-how-do-i-change-my-model-improvement-privacy-settings)）。

説明文は「チャットやコーディングセッションのデータを……トレーニングと改善に使用することを許可します」です。

![Claudeの設定画面。プライバシーの環境設定にある「AIモデルの改善に協力する」のスイッチがオフになっている](https://aicontent-note.com/wp-content/uploads/2026/09/img_0070_01.png "設定 → プライバシーの画面。「AIモデルの改善に協力する」をオフにした状態")

### 既定でオンなのか、と聞かれると

公式には「既定はオン」とも「オフ」とも書かれていません。
新しく登録する人は、登録のときにこの設定を選びます。
以前からの利用者は、2025年10月8日までにポップアップで選ぶ流れでした（[Anthropicの発表](https://www.anthropic.com/news/updates-to-our-consumer-terms)）。

私のアカウントは、オンになっていました。
設定を触った記憶はありません。
おそらく、**既定のまま**使っていたのだと思います。

「後で」を押したのか、読まずに通したのかは、正直に言うと分かりません。

【チェック】<br>
設定を見るのは1分。オンかオフかを、今この場で確かめる

## オフにして、何が変わったか

オンだった設定を、オフに切り替えました。
**変わることと、変わらないこと**を分けます。

| 項目 | オフにすると |
|---|---|
| これから始めるチャット・セッション | 今後のモデル学習には使われない |
| 保存済みの過去のチャット・セッション | 今後のモデル学習には使われない |
| 今後のチャット・セッションの標準保持期間 | 30日 |
| すでに始まっている学習・作られたモデル | 外れない |
| 安全性レビュー対象の会話 | オフでも、安全性の検出・ポリシー適用・安全性研究などに使われる場合がある |
| 自分から送ったフィードバック | オフでもモデル改善に使われる場合がある |
| 「位置情報メタデータ」 | 別の設定。連動しない |

過去のチャットも「previous or new chats」として、今後の学習には使われなくなります。
すでに始まった学習からは外れません（[プライバシーセンター](https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data)）。

【アラート】<br>
オフにしても、すでに始まった学習と、作られたモデルからは外れない

私がオフにした理由は、自分以外の情報を日常的に入れているからです。
切り替えに確認画面は出ず、使える機能も変わりませんでした。

**学習に使われることと、渡した情報が読まれることは別の話**です。
Anthropicは、学習に使うデータの機微な情報をフィルタまたは難読化すると説明しています。
利用者のデータを第三者に売ることはない、とも書いています（[Anthropicの発表](https://www.anthropic.com/news/updates-to-our-consumer-terms)）。

オンのときの違いは、入れた内容が将来の学習に入り、==あとから取り消せない==ことです。
渡した情報そのものをどうするかは、後半で書きます。

## 会社で使うと、Claude Pro・MaxとTeamは何が違うか

会社で使う前に見るのは、契約の種類です。
公式で確かめられた事実だけを並べます。

| | Claude Pro・Max | Claude Team |
|---|---|---|
| 公式の区分 | consumer users | commercial users |
| モデル学習 | 設定で選ぶ | 既定で使わない |
| 人数 | 1人 | 2〜150名 |

Claude Code公式は、Free・Pro・Maxを「consumer users」と呼びます。
Team・Enterprise・APIは「commercial users」です。
Pro・Maxはモデル改善を設定で選び、Teamは既定でモデル学習に使いません。

Teamの料金は、標準席が1席あたり月20ドル（年払い）か25ドル（月払い）です（[料金ページ](https://claude.com/ja/pricing)・米ドル表記）。

会社のメールアドレスで登録している人は、規約の「Business Domains」の項も見ておくといいです。
勤め先がAnthropicの企業契約を持つと、アカウントがそこに紐づく場合があります。

その場合、管理者がアカウントを監視・管理できる場合があります。
入力や出力などのMaterialsにも、アクセスできると書かれています。

【インフォ】<br>
**個人契約のPro・Maxは、学習に使うかを設定で選ぶ方式**。<br>
Teamは会社側の契約で、既定ではモデル学習に使わない

## 私が渡しているもの・渡さないもの

ここからは設定ではなく、渡した情報そのものの話です。
まず、私がClaude Codeに渡した記録から、そのまま並べます。

| 種類 | 実物の例 | 渡している？ | 決めた理由 |
|---|---|---|---|
| 取引先の会社名 | 営業リスト・求人情報から抽出した会社名 | 渡している | 分類と優先づけを任せるため |
| 領収書・経費台帳 | 領収書PDF（取引先名・金額）・経費台帳 | 渡している | 仕訳と集計を任せるため |
| 制作中の案件データ | ロゴ案・制作ルール | 渡している | 制作の下書きを任せるため |
| 自分のメディアのデータ | 記事本文・検索の数字・X投稿 | 渡している | 自分の情報なので迷わない |
| パスワード・ログイン情報 | WordPressなどの認証情報 | 渡していない | AIはログインしない・入力しないと決めている |
| クレジットカード・口座の情報 | カード番号・口座番号 | 渡していない | 財務情報は入れない |

6項目のうち3項目は、自分以外の情報でした。
それを、==モデル改善を許可する設定がオンの状態で送っていた==ことになります。

実際に学習に使われたかどうかは、利用者側からは確かめられません。
確かめられるのは、設定がオンだったところまでです。

【メモ】<br>
ローカルのClaude Codeは、PC側にも記録を残す。<br>
~/.claude/projects/ に平文で標準30日。cleanupPeriodDaysで変更可

顧客の情報を預けるかどうかは、職種ごとに分けて書いています。
弁護士向けは[弁護士業務の案件管理と書類作成に、Claude Codeを当てはめた](https://aicontent-note.com/claude-code-lawyer-case-management/)に。
社労士向けは[社労士業務の就業規則・36協定に、Claude Codeを当てはめた](https://aicontent-note.com/claude-code-labor-consultant-rules-agreement/)にあります。

## 渡さないための運用

渡さないようにする方法は、気をつけることではありません。
渡せない状態を、先に作っておくことです。

| やること | どう効くか |
|---|---|
| 読ませないファイルを設定で指定する | Claude Codeが.envなどを開けなくなる |
| ログインは人がやる | パスワードを入力する場面が、AIに回らない |
| 渡さないものをルールのファイルに書く | 毎回の判断に頼らなくなる |
| 資料はコネクタでつなぐ | つないだ中身そのものは学習の対象外。貼ると対象 |
| その場かぎりの相談はIncognito | 設定がオンでも学習に使われない |

いちばん上が、いちばん確実です。
Claude Codeの設定ファイルに、読み取りを断る指定を書けます。

【ペン】<br>
~/.claude/settings.json の permissions に deny を足す。<br>
公式の例は Read(./.env) と Read(./.env.*) の2行

私の設定には、この指定が入っていませんでした。
気づいた時点で、.envと鍵ファイルを読み取り拒否に追加しました。

公式ドキュメントの例もこの形です（[Claude Code公式](https://code.claude.com/docs/en/settings)）。
指定しておくと、AIが中身を開こうとした時点で止まります。

ログインについては、人がやると決めています。
AIに渡すのは記事や数字で、パスワードは入力しません。

自分以外の情報については、渡す前に一度だけ考えます。
その情報が外に出て困る相手が、自分ではなく取引先なら、渡す前に確認します。

## 渡してしまったときに、どこまでやるか

気づかずに渡していたと分かったら、まず何が起きるのかを見ます。
そのうえで、どこまでやるかを決めます。

### 渡すと、どうなるのか

まず、**渡した情報がすぐ誰かの目に触れるわけではありません**。
Anthropicの説明では、データは送るときも保存するときも暗号化されます。
社員は既定では会話を読めません（[プライバシーセンター](https://privacy.claude.com/en/articles/10458704-how-does-anthropic-protect-the-personal-data-of-claude-users)）。

起きるのは、次の5つです。
右端の列は、モデル改善の設定で変わるかどうかです。

| 何が起きるか | 実害になるとき | 設定で変わるか |
|---|---|---|
| 会話に残る | アカウントに入られた人や、共有リンクを開いた人が読む | 変わらない |
| PCに記録が残る | 共用のPCや、持ち出されたPCから読まれる | 変わらない |
| 学習データに入る | あとから取り消せない | オンのときだけ |
| 保持期間が延びる | 消し忘れた会話が長く残る | オンで5年・オフで30日 |
| 安全性レビューに当たる | 限られた担当者が読む場合がある | 変わらない |

パスワードやキーなら、読まれた時点で使われます。
身に覚えのないログインや、課金につながります。

取引先名や金額は、読まれても使われることはありません。
困るのは、自分ではなく相手の情報が外に出ることです。

【アラート】<br>
==渡してしまったときの危険は、オフにしても消えない==。<br>
オフが止めるのは学習だけで、渡した文字列は会話に残る

### 直すか、そこまでしなくていいかの線

私の線引きは1つだけです。
==その文字列だけで、誰かが何かをできるか==で分けます。

| 渡したもの | それだけで使えるか | やること |
|---|---|---|
| パスワード・APIキー・トークン | 使える | 無効にして作り直す。会話も消す |
| クレジットカード・口座の情報 | 条件つきで使える | 使われたら気づける状態にする |
| 取引先名・金額・案件の中身 | 使えない | 会話を消し、共有リンクを切る |

上の2つは、消すだけでは終わりません。
消しても、渡した文字列は変わらないままだからです。

いちばん下は逆で、無効にするという手がありません。
残っている場所を減らすことが、そのまま対処になります。

【グッド】<br>
会話を削除すると履歴からはすぐ消える。<br>
バックエンドからは30日以内に消え、今後の学習にも使われない

### 私がやったこと

Claude Codeの案内どおりに作業を進めていたら、その流れでAPIキーを渡していました。
自分から渡すつもりがなくても、手順に沿うだけで渡ることがあります。

気づいたあとは、元のキーを削除して作り直しました。
発行元の画面で数分あれば作り直せます。
作り直した時点で、渡したほうの文字列は使えなくなります。

### 変えるのが難しいとき

カード番号のように、簡単には変えられないものもあります。
その場合は、無効にするのではなく、使われたら気づける状態にします。

・利用のたびに通知が届く設定にする<br>
・明細を数日おきに見る<br>
・不安が残るなら、カード会社に連絡して再発行を相談する

ネット決済では、カード番号だけで通るわけではありません。
国内のEC加盟店は、2025年3月末までにEMV 3-Dセキュアの導入が原則として求められています（[経済産業省](https://www.meti.go.jp/press/2024/03/20250305002/20250305002.html)）。
本人認証が別に入るぶん、番号だけを知られた状態とは危険度が違います。

とはいえ、放っておくのとは違います。
気づける状態にしておくところまでが、最低限です。

## 渡す前に決めておく3つ

「安全か危険か」の二択にはなりません。
自分の設定と、入れているものを見てから決める話です。

1. 自分の設定を見る。オンなら、通常のチャットとセッションをモデル改善に使う設定になっている<br>
2. 入れているものを一度書き出す。自分の情報か、自分以外の情報か<br>
3. 自分以外の情報を日常的に入れるなら、扱いを決める<br>
（モデル改善をオフにする / Teamなどの商用プランを検討する / そもそも渡さない）

すでに渡していたものがあれば、使えなくするところまでを先にやります。
これは設定とは別に、やることが残る部分です。

==私はオフにしました==。
使い勝手は変わらなかったので、迷っている人は先に設定だけ見るのがいい気がしています。
