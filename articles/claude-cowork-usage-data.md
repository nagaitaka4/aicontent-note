# Claude Coworkの使い方｜実際の9割は開発以外だった

Claude Coworkは、日常の仕事をAIに任せるClaudeの機能です。
公開された利用データでは、ソフトウェア開発はわずか8.7%でした。
どこから使えるか、何に使われているか、どう使うかを整理します。

## Claude Coworkとは？Claude Codeとの違いと、どこから使えるか

Coworkを使うのに、新しいアプリを入れる必要はありません。
入口は、Claudeアプリのプロンプト入力欄にある切り替えです。
利用の条件は、有料プランに入っていることです。

・入力欄で「チャット」から「Cowork」へ切り替える<br>
・タスクを渡し、進み方を見ながら確認や方向転換をする<br>
・承認したフォルダのファイルを読み取り / 編集 / 作成する

なお、私はCoworkをまだ実務で使っていません。
この記事は、公開された一次情報と、Claude Codeを運用している側から見た読み方でまとめています。

Coworkはデスクトップ向けに先行して提供されていました。
2026年7月7日には、Web版とモバイル版もベータとして展開されています（[Claude Cowork公式ページ](https://claude.com/product/cowork)）。

Anthropicは2つの製品を正面から比較していません。
下の表は、Cowork側を公式の説明、Claude Code側を当ノートの既存記事から整理したものです。

|  | 主な用途 | 操作する対象 | 向いている作業 | 利用方法 |
|---|---|---|---|---|
| Claude Cowork | 渡したタスクを最後まで進める | 承認したフォルダのファイル | 調査・分析・資料作成など、複数手順の仕事 | アプリの入力欄で切り替える |
| Claude Code | 手元の作業環境を組み立てて動かす | 手元の作業環境のファイル | 基準や履歴を手元に残していく仕事 | コマンドラインから指示を出す |

くり返しになりますが、両者を並べた公式の比較は公開されていません。
セットアップから実際の使い方までは、次の記事にまとめています。

[Claude Codeとは何か？できること・使い方を実際に使って整理した](https://aicontent-note.com/claude-code-introduction/)

近い形のものに、2026年7月9日公開のChatGPT Workがあります。
どちらもチャットの中で情報を横断し、成果物まで作ります。
Coworkは、承認したフォルダが範囲です。
逆に、ChatGPT Workは接続したアプリで範囲が決まります。

[ChatGPT WorkとClaude Codeの違いと選び方](https://aicontent-note.com/chatgpt-work-claude-code-comparison/)

## 公開された利用データを見ると、ソフトウェア開発は8.7%だった

Coworkには、開発作業の道具という印象を持っていました。
Claude Codeの印象を、そのまま重ねていたのだと思います。
ところが公開データでは、開発より上に別の仕事が並んでいました。

【インフォ】<br>
調査対象は匿名化・集計済みのCoworkセッション120万件、60万を超える組織の分です

出典は、2026年7月7日公開の[Anthropic公式ブログ](https://claude.com/blog/how-people-are-using-claude-cowork)です。
収集期間は2026年5月11日〜31日で、各割合はこの120万セッションを母数にしています。

| カテゴリ | 割合 | 具体的に含まれる作業例 |
|---|---:|---|
| 業務プロセス・オペレーション | 33.4% | オンボーディング用チェックリストの作成 / スプレッドシートの照合 |
| コンテンツ制作・コピーライティング | 16.4% | スライド作成 |
| ソフトウェア開発 | 8.7% | — |
| DevOps・インフラ | 7% | — |
| リサーチ・情報分析 | 6.4% | — |
| データ分析・BI | 5.8% | — |
| 文書処理・情報抽出 | 4.1% | — |
| 営業・レベニューオペレーション | 4% | — |

ただし、これは3週間分のスナップショットです。
この期間の利用実態を示す数字として読みます。

## 最も多かったのは、担当業務になっていない作業だった

Anthropicは、この実態に呼び名を与えています。
the work around the work、つまり仕事の周りにある仕事です。
多くの職種に含まれるのに、本人の担当業務ではない作業です。

【ポイント】<br>
上位2カテゴリで全体のおよそ半分になると、Anthropic自身が明記しています

公式が例として挙げているのは、次のような作業です。

・ステータス更新の作成 / スライド作成<br>
・調査結果の要約 / オンボーディング用チェックリストの作成<br>
・スプレッドシートの照合 / 表計算の数式作成<br>
・フォルダの整理 / ファイルの重複削除

## では、Claude Coworkを何に使えばいいのか

ここからは、私なら仕事をどう切り出すかを考えます。
機能一覧から選ぶのではなく、普段の作業を起点にしました。
見た順番は、次の3つです。

### 1. 毎回繰り返している作業を探す

最初に見たのは、同じ手順でやっている作業です。
同じ場所を開き、似た内容を確かめて、別の場所へ書き写す。
手順を言葉にできるなら、渡せる形にはなっていると考えました。

### 2. 複数のファイルや情報をまたぐ作業を探す

次に見たのは、一画面では終わらない作業です。
Aを確認してBを更新し、最後にCを作る形が当てはまります。
渡す単位は作業そのものではなく、この流れごとだと考えました。

### 3. 最終成果物の前後にある作業を探す

最後に、成果物の前後へ目を向けました。
作る前には調査と整理があり、作った後には確認と更新が残ります。
中心の作業だけを見ていると、この前後が抜け落ちます。

【ポイント】<br>
渡す単位は、機能の一覧ではなく手元の作業のほうから決まりました

同じ見方を業務単位まで落とした記事が、こちらです。

## コンテンツ運用をしている側から、この数字をどう読むか

前章の見方を、自分の運用に当てはめます。
AIに任せる場面は、執筆そのものだけでなく、その周りにもかなりありました。
現在の分担は、次のとおりです。

| 工程 | 現在の任せ方 |
|---|---|
| 企画・ネタ集め | 定期リサーチを自動実行し、記事ネタをファイルに蓄積している |
| 調査 | AIが一次情報を検索・取得し、出典URLまで記録する |
| 構成 | AIと数往復して詰める。ここは人が判断する比重が大きい |
| 執筆 | 構成が固まっていればAIに任せられる |
| 画像 | 生成プロンプトはAIが作成。リサイズ・リネームもAIが実行する |
| 入稿・公開 | 人が手動で行う |
| 計測 | AIがSearch Consoleの数字を取得し、ファイルに記録する |
| 改善 | 数字を見て次に何をするかは人が決める |

このメディアの運用では、人が判断する工程と手動の工程が残っています。

コンテンツ制作が16.4%で2番目だったことにも、納得感があります。
自分の運用でも、記事を書く以外の工程にAIが入っているためです。

どの業務が向くかは、こちらで職種ごとに整理しています。

## ただし、この数字だけで「Coworkは開発者向けではない」とは言い切れない

Anthropic自身も、開発者の使い分けを説明しています。
利用比率と向き不向きは、同じ話ではありません。
押さえておきたい点が4つあります。

1. コードを書くとき、開発者はCoworkよりClaude Codeを圧倒的に使うとAnthropicは書いています。ただし、開発者もCoworkは使っています。そこでの中身は、つなぎやコミュニケーション中心の仕事です。これはソフトウェアエンジニアリングを含む、あらゆる職種を取り巻く仕事だとしています
2. 利用カテゴリの比率は、その製品が最も得意な用途を示すとは限りません
3. 利用者層や調査対象が変われば、比率も変わります
4. 8.7%は、開発に向かないという意味ではありません

確認できるのは、Coworkという製品で開発が8.7%だったことまでです。
AIエージェント全般の利用分布を示す数字ではありません。

数字を小さく扱う必要も、大きく広げる必要もないと思っています。
示された範囲が分かっていれば、使いどころの判断もぶれにくくなります。

## まず自分の「仕事の周りにある仕事」を書き出してみる

私が次にやるのは、時間を取られている作業の書き出しです。
その中から、繰り返しとファイルをまたぐ流れを見ます。
Coworkに触れたら、分かったことをノートに残します。
