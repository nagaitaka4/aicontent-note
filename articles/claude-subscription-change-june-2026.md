# Claudeの課金が6月から変わる。影響がある使い方・ない使い方

2026年6月15日から、Claudeのサブスクリプション構造が変わります。

「影響があるのか？」「何を確認すればいいのか？」という疑問を持った方向けに、変更内容と利用方法別の影響を整理しました。

---

## 先に結論：手動利用メインなら影響はほぼない

結論を先に書いておきます。

claude.aiで会話したり、ターミナルで手動Claude Codeを動かしているだけなら、今回の変更による影響はほぼありません。

影響が出るのは、Agent SDKや`claude -p`を使った自動化・大量実行系の利用です。

> 【ポイント】
> 「手動で自分が指示して使う」か「プログラムが自動で大量に呼び出す」かで、影響の有無が大きく変わります。

### 影響が出るのは自動化・大量実行系

次の利用が、今回の変更で「別枠クレジット」から消費されるようになります。

・Claude Code SDK
・Agent SDK
・GitHub Actions
・API系自動化
・`claude -p`の大量実行

### 手動のClaude Code利用は対象外に近い

次の利用は「インタラクティブ利用」に分類され、今回の変更対象外です。

・通常のclaude.ai
・手動Claude Code（ターミナルで会話ベース利用）
・Claude Cowork

---

## ① 何が変わるのか

変更点を整理します。

### まず対象になるもの

・Claude Code SDK
・Agent SDK
・GitHub Actions
・API系自動化
・`claude -p`の大量実行

これらは6月15日から、通常の利用枠とは別の「クレジット枠」から消費されるようになります。

### 対象外に近いもの

・通常のclaude.ai
・手動Claude Code（会話利用）
・Claude Cowork

これらは今まで通りの利用上限の中で使えます。

### これまでの仕組み

これまでは、月額料金を払えば手動利用も自動化利用も同じ利用枠内でカバーされていました。

### 6月からの変更内容

2026年6月15日から、**自動化・プログラマティック利用が「別枠クレジット」として切り出されます。**

> 【インフォ】
> 「プログラマティック利用」とは、Agent SDKや`claude -p`など、プログラムが自動でClaudeを呼び出す形の利用を指します。人間が手動でキーボードを打って会話する「インタラクティブ利用」とは別扱いになります。

月額費用自体は変わりません。自動化利用に使えるクレジットに上限が設けられる、という変更です。

### プラン別クレジット額（Pro・Max 5x・Max 20x）

各プランに割り当てられる別枠クレジット額は次のとおりです。

| プラン | 別枠クレジット（月額） |
|---|---|
| Pro | $20 |
| Max 5x | $100 |
| Max 20x | $200 |

### 注意点：非繰り越し・月末失効

> 【アラート】
> 別枠クレジットは月末にリセットされます。未使用分は翌月に繰り越せません。使い切れなかった分はそのまま失効します。

---

## ② なぜこうなったのか

なぜこの変更が起きたのかを整理しておきます。

### 2月の第三者エージェント利用禁止から5月の分割課金再開まで

Anthropicは2026年2月に、サブスクリプションプランでの第三者エージェントツール利用を一度禁止しました。4月にはその禁止をさらに強化。

5月に方針を転換。「禁止」ではなく「別枠での分割課金」という形で再開されることになりました。第三者エージェントの利用は認めつつ、そのコストは別枠で管理するという設計です。

### 推測できる背景

公式からは詳細な理由は示されていません。ただ、背景としては次のことが読み取れます。

・大量の自動化利用が増え、定額モデルの採算に影響が出てきた
・通常利用と自動化利用のコストを分離する必要があった
・個人の手動利用と、業務・開発での大量利用を切り分けたかった

## ③ 影響がある使い方・ない使い方

利用方法別に整理します。

### まず結論比較表

| 使い方 | 影響 |
|---|---|
| claude.aiで会話 | 小 |
| 手動Claude Code | 小 |
| Cursor連携 | 中（利用方法次第） |
| GitHub Actions | 大 |
| Agent SDK | 大 |
| `claude -p`大量実行 | 大 |

### 影響が大きい使い方

次の利用は別枠クレジットから消費され、影響が出ます。

・Agent SDKを使ったスクリプト実行
・`claude -p`（非インタラクティブモード）での自動実行
・Claude Code GitHub Actionsの利用
・Agent SDK経由のサードパーティアプリ

### 影響が小さい使い方

・ターミナルでClaude Codeを手動操作する
・claude.ai（web / desktop / mobile）でチャット利用
・Claude Coworkの利用

### 迷ったときの判断ポイント

> 【チェック】
> 「自分がキーボードを打って指示しているか、プログラムが自動で呼び出しているか」で区別するとわかりやすいです。CursorのようなIDEは手動で会話している範囲では影響が小さいですが、自動補完を大量に処理している場合は確認が必要です。

---

## ④ 手動利用で実際に確認してみた

自分の使い方に当てはめて確認しました。

### 私の使い方

・記事制作がメイン
・Claude Codeはターミナルで会話ベース利用
・CLIの実行はすべて手動
・1日に数回セッションを開いて操作する程度

Agent SDKは使っていません。`claude -p`の自動化スクリプトも動かしていません。

### 確認した結果

この使い方だと、今回の変更による影響はほぼありません。

インタラクティブ利用は変更対象外なので、利用上限も変わりません。「変更が来た」と聞いて確認しましたが、自分の利用範囲では追加コストも制限の変化も発生しないとわかりました。

### 自動化を広げる場合に気になること

今回確認して感じたのは、自動化利用を増やしていく場合はコスト管理の視点が必要になるということです。

「とりあえず自動化する」「スクリプトを回しっぱなしにする」という使い方は別枠クレジットを消費します。クレジットが尽きると、設定次第で翌月まで自動化が止まります。

手動利用メインの今のうちに、自動化した場合のコスト感覚は把握しておきたいと思っています。

---

## ⑤ 6月15日までに確認しておくこと

### 自分が自動化利用しているか確認する

まず、自分の利用の中に「自動化・プログラマティック利用」が含まれているかを確認します。手動でClaude Codeを使っているだけであれば、とくに対応は必要ありません。

### GitHub Actionsを使っている人は要注意

Claude Code GitHub Actionsを設定している場合、6月15日以降は別枠クレジットから消費されます。実行回数と消費量を事前に把握しておくことを推奨します。

### `claude -p`を常用している人は確認推奨

`claude -p`（非インタラクティブモード）を使ったスクリプトを走らせている場合も同様です。月間の実行量を確認し、別枠クレジット内に収まるかを確認してください。

### 通常会話メインなら過度に心配しなくてよい

claude.aiでの会話利用や手動Claude Codeのみの場合は、過度に心配する必要はありません。

---

## ⑥ 今回の変更で感じたこと

### AI企業は「大量自動化」と「通常利用」を分離し始めている

今回の変更は、Anthropicだけの話ではないと感じています。定額モデルで大量の自動化利用をカバーし続けることには限界があります。AI企業全体が「通常利用者」と「大量自動化利用者」を切り分ける方向に動いているように見えます。

### "使い放題"前提は今後減る可能性がある

自動化が進むほど、定額の「使い放題」前提は崩れていきます。大量に処理を回す用途には、それに見合った料金体系が適用される流れになっていくでしょう。

### 個人利用と業務利用の境界が明確化していきそう

手動でClaude Codeを使う個人ユーザーと、Agent SDKで業務プロセスを自動化する開発者・企業が、同じ料金体系で扱われる時代は終わりに近づいているかもしれません。

### AI活用は「どこを自動化するか設計する時代」になってきた

「便利だから自動化する」から「コストと効果を設計した上で自動化する」という意識が必要になってきます。個人レベルでも、「どこを自動化してどこは手動にするか」を考える時代が来ています。
