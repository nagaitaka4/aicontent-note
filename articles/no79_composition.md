## Agent Skillsの作り方：フォルダとSKILL.md 1枚から
→ 答え（マーカー）：最初に書くのは「いつ使うか」の説明と、上から順に進める手順だけ
→ 【チェック】作る手順（Claude Codeの場合・公式どおり）
   ・**フォルダを作る**：全部の作業で使うものはホームフォルダの.claude/skills/、1つのプロジェクトだけで使うものはそのプロジェクトの.claude/skills/の下に、スキルの名前のフォルダを作る
   ・**SKILL.mdを置く**：冒頭に「いつ使うか」の説明（description）、その下に手順
   ・**長い資料は別ファイル**：SKILL.mdから「この資料を読む」と書いて読ませる（公式は500行未満を勧めている・公式にリンク）
→ 例（私の実物を要約）：記事ごとに必ず作るアイキャッチの指示。説明は「添付した参考画像をもとに、記事用のアイキャッチの指示を1つ作る」。手順の1つ目は、デザインの決まりのファイルを毎回読み直すこと
→ 【メモ】昔の作り方（.claude/commands/に置くファイル）も、今はスキルと同じように動く。私のアイキャッチの手順はこの形のまま使っている

## 8つのコツ：中身を書く4つ（①〜④）
→ 1〜2文：8つのコツは、風音屋TechBlog「AIエージェント向けの業務手順書（Agent Skills）の設計方法」の整理をもとにした（リンク）。元の記事は日程調整の例。ここではブログ運用の手順書に置き換える。私の手順書の多くはCLAUDE.mdとルールファイルにあり、スキルにしているのは一部
→ 表2：コツ ／ ブログ運用での例（8行・1列目を太字・①②⑤にマーカー）
   ・①判断基準を書き出す ／ 対象が曖昧なときだけ聞く・記事に無いことは書かない
   ・②決まった計算はプログラムに ／ Xの文字数は数えるプログラム、言い回しはAI

### ①判断基準と「聞かずに進めてよいこと」を書き出す
→ 2〜3文：手順だけ書くと、AIは迷うたびに確認しに来るか、勝手に決める。アイキャッチの手順書には「対象の記事が曖昧なときだけ聞く」「記事に無いことは書かない」と、聞くときと聞かずに進めるときの線を書いている

### ②答えが1つに決まる計算は、プログラムに任せる
→ 答え：数える・測る作業はプログラム、言い回しを選ぶのはAI
→ 2〜3文（実例）：Xは日本語を2、英数字を1と数えて上限が決まる。AIに数えさせていた頃は、まだ入るのに下書きを削っていた。今は文字数を数えるプログラムを手順書に書き、AIはその結果を見て直すだけ

### ③出す先ごとに、書いてよい範囲を書き分ける
→ 2文：同じ数字でも、自分とAIだけが見る作業メモとXでは出せる範囲が違う。私はサイトのクリック数を作業メモには書くが、Xには出さないと手順書に書いている

### ④手順と、ときどき見る資料を分けて読ませる
→ 2〜3文：1つのファイルに全部書くと、AIも人も読めなくなる。毎回の判断基準と、カテゴリの一覧のような参照するだけの資料を別のフォルダにした。毎朝のXの準備の手順書も、月曜と金曜だけ読む調べ物の手順を別ファイルに分けている。アイキャッチの手順書も、デザインの決まりは書き写さず、ファイルを読ませるだけ

## 止めて、試して、育てる4つのコツ（⑤〜⑧）

### ⑤公開・投稿の直前は、人が押す
→ 2〜3文：記事は下書きを作るところまでAIに任せ、公開ボタンだけ私が押す。下書きの画面で全体を読み直してから出したいから。毎朝のXの準備の手順書にも「候補を出すだけ。判断と実行は人がやる」と書いた
→ 【ポイント】確認を求めるときは、何度も聞かずに「Aを推奨・理由」の形でまとめて1回聞かせる

### ⑥プログラムを直したら、わざと違反の例で確かめる
→ 2〜3文：元の記事は、決めたルールをテストのプログラムで固定している。私はテストのファイルまでは持っていない。代わりに、文字数などを測るプログラムを直すたびに、わざと引っかかる文を入れて止まるか確かめている

### ⑦経緯を知らない、まっさらなAIで試す
→ 2〜3文：作った会話のAIは、書いていないことまで知っている。私は構成案を出す前に、会話を持たない別のAIに、構成案とレビューの見方だけ渡して読ませる。「この稿で何を狙ったか」は渡さない
→ 1文：スキルも同じで、作った会話とは別のまっさらなAIに手順書だけ渡して動かすと、迷った所が書き漏れとして見える

### ⑧失敗したら、なぜ足したかを経緯のファイルに残す
→ 答え（マーカー）：一文を足したら、なぜ足したかを経緯のファイルに残す。手順書の本文は短いまま保つ
→ 2〜3文（実例）：Xの投稿が、普段と違う口調のままチェックを通ったことがある。そのときは口調を調べる項目をチェックに足し、経緯を別のファイルに残した。ルールファイルを整理して短くしたときも、経緯は消さずに移した

## 何からスキルにするか：手間×回数が大きい作業を1つ
→ 答え（マーカー）：手間×回数が大きい作業を1つ選び、手順書1枚から始める
→ 【チェック】選び方（元の記事の「何から始めるか」をブログ運用に置き換え）
   ・**手間×回数が大きい作業から1つ**：記事ごとのアイキャッチの指示、毎朝のSNSの準備など
   ・**結果の保存先も書く**：AIは前の会話を覚えていないので、終わりに引き継ぎのメモを残す手順まで
→ 1文：8つを最初からそろえなくていい。うまくいかなかった所に1つずつ足す
