# X投稿キュー（順位付き・完成下書き）

X運用半自動化の中核ファイル。**ここにあるのは「そのまま投稿できる下書き」のみ**。素材（未下書き）はideas.md、投稿済みはposts-stock.md／published.mdへ。

## このキューの判断の原点（Xの目的・x-post-flow.mdより）

バズを狙うのではない。すべての下書き・ランク判定・順位は以下に照らす。

- **フォロワー獲得**：「Claude Code × 実務」の視点を持つ人と繋がる
- **記事への送客**：投稿が記事を読む理由になる
- **ポジション確立**：「Claude Codeを実際の業務に当てはめて考察する人」＝「非エンジニアがClaude CodeとAIでメディアを回している人」として認知される
- 最終導線：投稿 → 記事 → 信頼 → 問い合わせ → コンテンツ運用代行の受注

ビューが伸びそうでも、このポジションとズレる下書きはキューに入れない。

## キューのルール

- **理想は常時10本（HR級）。**想定ペースは**週2〜3本**なので、10本＝約1ヶ月分にあたる。**在庫5本未満で取材／★★★★★が2本未満でも取材**（判断基準は`rules/x-post-flow.md`「キュー在庫の判断基準」）
- ランクは3条件の該当数で決まる（2つ以上=★★★★★／1つ=★★★★☆／0個=キューに入れない）
- **軸バランス（2026-08-11改訂）**：キュー全体で**軸②50%／軸①40%／軸③・④10%**に寄せる。軸②が痩せたら`ideas.md`のリサーチ由来から補充する（毎日8:00の`ai-trends-daily`が自動で供給する）
  - **軸②は「自分の使い方に影響する変更」のみ入れる。**新モデル発表の報告だけの下書きはキューに入れない（実測で3〜9ビュー帯）
- **順位は固定しない**。「次の投稿内容を教えて」のたびに、直近の投稿履歴（published.md・posts-stock.md）・軸の連続・開き方の被り・旬ネタの有無を確認して再評価する
- 順位の基準（2026-08-21改訂）：**読者の世界の話か ＞ ランク ＞ 鮮度 ＞ 軸・テーマのバランス（同軸連続を避ける）＞ テーマを育てる順序**
  - **「読者の世界の話か」を最初に見る。**製品・料金・制限・検索の変化＝読者に起きる話。自分のルール・チェック・リライトの裏側＝**3条件を満たしていても初見の読者には内輪の話**。2026-08-21にユーザー指摘（「内輪の言葉だらけで初見では読めません」）。この時点で上位9本のうち7本が裏側の話で占められていた
- 全下書きは`operations/x-count.py`で実測済み・冒頭主語ルール適用済み・過去投稿と重複チェック済みの状態で置く
- **キューの下書きも、提示する直前に出力前チェック7項目＋文体（丁寧体基本・改行・文末）を毎回通す。**「実測済み」は文字数の話であって、チェック済みの意味ではない（2026-08-21：PLUS3-気が常体一段落のままユーザーに提示され、指摘を受けた。文末の実測は「ます」51「ました」39「です」23「でした」14に対し「だった」4＝丁寧体が投稿の声）
- **順位はサマリー表だけで管理する。本文の見出しに順位を書かない**（2026-08-19）。表と見出しの2箇所で持つと必ずずれる（8/19の棚卸しで見出しのほぼ全部が実際の順位と食い違っていた）
- **投稿・リプライで使った実測データは、その下書きにも注記する。**同じ数字を投稿とリプライの両方で出すと重複になる（8/19にM02-01で発生）
- 運用ループ・補充ルールの詳細は `rules/x-post-flow.md`「投稿キュー運用」を参照
