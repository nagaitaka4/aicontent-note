# Claude Code × 記事制作 全体フロー

最終更新: 2026-04-27（S-14・S-15から抽出）

---

## 工程の全体像

```
① キーワード・検索意図・方向性を自分で決める（人間）
        ↓
② Claude Codeに構成（H1/H2/H3）を出力させる
        ↓
③ 方向性・抜け漏れ・順序を確認して調整する（人間）
        ↓
④ 構成＋トンマナ＋記事方針をセットで渡す
        ↓
⑤ H2単位で本文下書きを出力させる
        ↓
⑥ 出力を「素材」として受け取り、自分の言葉に変換する（人間）
        ↓
⑦ 実体験・具体例を加えて完成させる（人間）
        ↓
⑧ 入稿・整形・公開（S-16で検証予定）
```

---

## 工程の分類（Claude Codeに向いているかの判断軸）

業務を「生成・整理・判断」の3つに分けると、どこをAIに任せられるかが明確になる。

| 工程 | 分類 | Claude Codeに任せられるか |
|---|---|---|
| キーワード・方向性の決定 | 判断 | ✕ 人間がやる |
| 構成展開（H2/H3の骨格） | 整理 | ◎ 得意 |
| 本文の下書き生成 | 生成 | △ 素材として受け取る |
| リライト・言い換え | 整理・変換 | ◎ 得意 |
| 実体験・具体例の挿入 | 生成（経験ベース） | ✕ 人間しか書けない |
| 事実確認・数値チェック | 判断 | ✕ 人間がやる |
| トンマナの維持 | 整理 | ◎ ルールを渡せば得意 |

## Before / After（ChatGPT → Claude Code）

### Before
- トンマナ・記事方針を毎回説明し直す必要があった
- 記事全体を一括生成すると後半で軸がブレた
- 前回記事との関係性はゼロから伝え直し
- 構成のやり直しが頻繁に発生した

### After
- ルールをファイルに蓄積 → 初回設定のみで毎回引き継がれる
- H2単位で分割出力 → 軸のブレが減る
- 変わったのは「速さ」ではなく「手戻りの少なさ」と「継続性」

## この構造は他業務でも共通する

「情報を整理して構造化する」フローは業種を問わない。

- 資料作成（情報 → スライド骨格）
- 企画書（課題と解決策 → 構成）
- 議事録（発言 → 要点の構造）
- 法律事務所の文書作成（雛形 → 案件に合わせて変換）
- マニュアル更新（既存テキスト → 最新情報に修正）
