# シリーズ企画：Claudeに株の売買判断をまかせてみた

## コンセプト

「もし投資の判断をAIに全部まかせたら、どうなるのか？」

そのワクワクする問いから始まり、実際にゼロからシステムを作り、
毎日動かして、AIがルールを学習・改善していく様子を記録するシリーズ。

投資というリアルなテーマが入り口。
たどり着く本質は **「AIが継続運用できる構造の設計」**。

**「AI継続運用シリーズ」第1弾。**
同じ構造を記事企画・問い合わせ管理・営業記録・ライティングルール改善などに横展開予定。

> 免責：投資助言ではない。AIエージェント開発の実験・学習コンテンツ。

---

## このシリーズのトーン

「完成品を見せる」ではなく「運用しながら改善している」をそのまま見せる。

実況型コンテンツなので、構成は固定しているが記事テーマは運用状況に合わせて柔軟に変える。

積極的に前面に出すもの：
- Claudeが意味不明な判断をした
- プロンプトが崩壊した
- JSONが壊れた
- 人間側のルールが曖昧で失敗した
- 運用して初めて欠陥に気づいた
- AIの反省・ルール変更の経緯

泥臭い実体験があるから信頼が生まれる。

---

## 核心メッセージ

「AIに株を選ばせる」というワクワクする実験から始まったが、
作っていくうちに気づいた。

**これは投資の話ではなく、AIに継続的な業務を運用させる構造の話だ。**

そしてもう一つ気づいたこと。

**「AIに任せる」ではなく「AIと一緒に設計する」。**
ルール設計・情報整理・改善ループ・レビュー——これが全部セットで機能する。

このシリーズで作ったシステムの設計は、そのままコンテンツ運用に転用できる：

| 投資システムで作ったもの | コンテンツ運用への転用 |
|----------------------|-------------------|
| `patterns.md`（投資ルールファイル） | 編集方針・運用ルールファイル |
| `lessons.md`（日々の学びを自動蓄積） | 運用ナレッジの自動蓄積 |
| 4ステップ運用フロー | 業務フロー設計 |
| 日次振り返りレポート | PDCAの自動化 |
| AIがルールを自己改善 | AIが運用品質を継続改善 |

## シリーズ構成（全5回）

### #01 「AIに業務を継続運用させる」とはどういうことか
- なぜ投資シミュレーションをテーマに選んだか（毎日の判断・数値での評価・明確なルール）
- システム全体像（Next.js + FastAPI + SQLite + Claude API）
- 最初は20銘柄ウォッチリスト → 236銘柄ユニバースに拡張した経緯
- 毎日の4ステップ運用フロー（市場調査 → 銘柄調査 → AI判断実行 → 振り返り）
- この構造がコンテンツ運用とまったく同じ設計思想であること

### #02 AIに判断させるための設計思想
- 236銘柄から毎日40銘柄をアルゴリズムで抽出してClaudeに渡す仕組み
  （※Claudeが見るのは40銘柄のみ。これは設計上のトレードオフ）
- テクニカル指標（RSI・移動平均・出来高比率）を数値でプロンプトに渡す
- プロンプト設計の構成（ルール・状況・候補・学び・出力フォーマット）
- JSON出力の強制とパース処理
- 「AIに渡す情報の質と量」が判断品質を決める

### #03 AIが自己学習するナレッジシステムの設計
- `patterns.md`（ルール）と`lessons.md`（学び）の2ファイル構造
- 振り返りレポート：取引結果 → AIが評価 → lessons.mdに自動保存
- AIが提案したルール改善を人間が承認 → patterns.mdに反映
- 失敗例：「追記すべきルール」という見出しがAIを混乱させた問題
- この設計がコンテンツ運用代行の思想に直結する理由

### #04 非エンジニアがClaude Codeで作れた理由
- Trading Terminal風ダークUIをNext.jsで作った（デザインの意図と視覚的インパクト）
- コードより「何を作りたいか」の対話が中心だった
- Claude Codeで設計・実装・バグ修正を全部対話で進めた
- 設計速度が変わった・非エンジニアでもここまで作れた
- Perplexityとの連携・メールアラート・自動監視の実装
- UIスクショのX投稿との相性（AI判断・反省・ルール変更を実況コンテンツ化）

### #05 動かして分かったこと・この構造が応用できる場所
- 初トレード・想定外のバグ・ルールが育っていく面白さ
- 「AIに任せる」ではなく「AIと一緒に設計する」という感覚
- この構造をコンテンツ運用に転用するとどうなるか
- 2週間後にクラウド移行してどこからでも動かせる状態にする予定
- 「AIが継続運用できる構造」を他の業務に展開する可能性

## X（旧Twitter）との連携戦略

Trading Terminal風ダークUIはスクショ投稿と相性が良い。
以下を実況コンテンツとして定期投稿できる：

- 今日のAI判断（何を買った・売った・その理由）
- 損益の推移（ドキドキ感がそのままコンテンツになる）
- AIの反省・lessons.md更新内容
- ルール変更の経緯（なぜ変えたか・何が問題だったか）

**「AIが今日何を選んだか」という投資のドキドキ感を入口に、**
**「なぜそう判断したか・どう学習したか」という構造の話に自然に誘導する。**
フォロワーが増えればそのままシリーズ読者になる。

## マネタイズ戦略

シリーズ本体は無料で信頼を獲得し、構造・テンプレートをnote販売する。

```
シリーズ（無料）
  └── 信頼・読者獲得・AIコンテンツ運用メディアとしての認知

note販売（有料）
  ├── patterns.md / lessons.md 設計テンプレート
  ├── AIに継続運用させる4ステップ業務フロー設計ガイド
  └── プロンプト集（判断エンジン・振り返り・自己改善）

代行（外注）
  └── 「この構造をあなたのビジネスに作ります」
```

シリーズ = 信頼 → note = 再現 → 代行 = 外注

## このシリーズの位置づけ

「投資記事」ではなく「AI運用設計の実践記録」。
メディア全体のコンセプト「AIが継続運用できる構造を作る」と直結している。

**「AI継続運用シリーズ」第1弾として横展開できる：**

| 第1弾（本シリーズ） | 横展開候補 |
|-----------------|----------|
| Claudeに株の売買判断をさせる | Claudeに記事企画を運用させる |
| patterns.md = 投資ルール | patterns.md = 編集方針 |
| lessons.md = 取引の学び | lessons.md = 運用ナレッジ |

同じ構造で別業務に展開するたびに「この設計の汎用性」が証明されていく。
