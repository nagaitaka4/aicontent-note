# クラウド版への依頼文：公開記事の「古くなっている可能性がある記述」を洗い出す（2026-09-28）

## 使い方（ユーザーの手順）

1. Claude Code デスクトップ版で新しいセッションを開き、**Local ではなく Cloud** を選ぶ。リポジトリは `nagaitaka4/aicontent-note`。**入力欄の横のモードは「Auto」を選ぶ**（クラウドで選べるのは Accept edits／Plan／Auto の3つ。ファイルの編集はどれでも事前に許可される。Bypass は選べない・公式 permission-modes）
2. 下の依頼文の `【担当】` を `1/3` にして貼り付けて送る
3. 同じことをあと2回（`2/3`・`3/3`）。**3つのセッションが同時に動く**
4. Macを閉じてよい。終わると、それぞれプルリクエスト（GitHub上の変更の提案）ができる
5. 翌朝、CCに「クラウドの結果を見て」と言う（CCが3本のプルリクエストを読んでまとめる）

⚠️ 普通のクラウドセッションは、Autoでも確認や質問で止まることがある。止まっても、戻ってきて答えればそこから続く（公式：`you can still answer when you come back, up to environment expiry`）。ただし放っておく時間が長いと環境が回収され、裏で走っていた作業は戻らない。確認で止まらずに最後まで走らせたいなら「ルーティン」（公式：許可モードの選択が無く、一部の操作を除き承認で止まらずに走る）

⚠️ 記事そのものは書き換えさせない（報告ファイルを1つ作るだけ）。書き換えは結果を見てから、いつものセッションで決める。

## 依頼文（ここから下を貼る。`【担当】`だけ変える）

```
【担当】1/3

このリポジトリはブログ「AIコンテンツ運用ノート」の記事置き場です。公開済みの記事の中から、「書いた時点では正しかったが、今は古くなっている可能性がある記述」を洗い出してください。記事は書き換えないでください。

## 対象
- articles/ 直下の .md のうち、先頭のfront matterに `status: published` とあるものだけ
- それを front matter の `no:` の小さい順に並べ、3等分したうちの【担当】のグループ（1/3＝最初の3分の1、2/3＝真ん中、3/3＝最後。割り切れない分は3/3に入れる）
- 担当の記事は本文を最後まで読む

## 探すもの（時間がたつと変わりやすい記述）
1. モデル名・バージョン（例：Opus、Sonnet、Haiku、Fable、GPT-◯、Gemini ◯）
2. 料金・プラン名・プランの中身（月額、ドル、円、Pro、Max、Plus など）
3. 上限・回数・制限（5時間制限、週の上限、回数、文字数 など）
4. 機能の有無（「〜はできない」「〜が使える」「まだ〜ない」）
5. 時期に頼った言い方（「現在」「最新」「今は」「〜月から」「予定」「近々」）

## やってはいけないこと
- 記事ファイルを書き換えない
- ネットで調べて正誤を決めない（この環境では公式サイトを開けない）。**「間違っている」と断定しない**。判断はすべて「要確認」とし、なぜ古い可能性があるかと、何を見れば確かめられるかを書く
- 推測で公式ページのURLを作らない。確かめ方は「Anthropicの料金ページ」「OpenAIのリリースノート」のように名前で書く

### 2. 一覧（表）

### 3. 作業の記録
- 読んだ記事の no の一覧
- 迷った箇所（入れるか迷ったもの）があれば、その理由
```
