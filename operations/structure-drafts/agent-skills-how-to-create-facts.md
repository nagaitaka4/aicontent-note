## 5. 公式（Claude Code Docs「Claude をスキルで拡張する」・英語版で確認し、リンクは日本語版）

リンク：https://code.claude.com/docs/ja/skills （2026-11-05確認・200）

- スキル＝`SKILL.md`ファイルに指示を書くと、Claudeが関係するときに使う。`/スキル名`で直接呼ぶこともできる
- 作る目安：「同じ指示、チェックリスト、または複数ステップの手順をチャットに何度も貼り付けている場合、または CLAUDE.md のセクションが事実ではなく手順に成長している場合」
- CLAUDE.mdとの違い：**スキルの本体は使うときだけ読み込まれる**（CLAUDE.mdは毎回）。長い参考資料も必要になるまでほぼコストがかからない
- 置き場所：個人＝`~/.claude/skills/<スキル名>/SKILL.md`（そのマシンの全プロジェクト）／プロジェクト＝`.claude/skills/<スキル名>/SKILL.md`（コミットすればチームも使える）
- SKILL.mdの中身：`---`で囲んだ冒頭（フロントマター）と本文。`description`はClaudeがスキルを自動で読み込むかを決める手がかり（公式は「推奨」）。`name`を省くとフォルダ名がコマンド名になる
- 説明（description）と本体の読まれ方：**スキルの一覧として説明は毎回読まれ**（説明と`when_to_use`を合わせて1,536文字で切り詰め・「主要なユースケースを先頭に」）、本体は使うときだけ
- 本体の書き方：「本文自体は簡潔にしてください」「どのように、またはなぜ行うかを説明するのではなく、何をすべきかを記述し」（同ページ・2026-11-05確認）＝⑧の「理由」は手順書の本文ではなく経緯のファイルに残す、と合う
- サポートファイル：資料・例・スクリプトを同じフォルダに置き、SKILL.mdから参照する。**「SKILL.md は 500 行未満に保ってください。詳細な参照資料は別のファイルに移動してください。」**
- カスタムコマンドはスキルに統合：`.claude/commands/deploy.md`と`.claude/skills/deploy/SKILL.md`はどちらも`/deploy`になり同じように動く。既存の`.claude/commands/`も動く（新規はスキルを推奨）
- Agent Skillsはオープンスタンダードで、複数のAIツールで使える（公式の記述・agentskills.io）
- Claudeのアプリ（claude.ai）のスキルは、Claude Codeのターミナルでも同期される（同ページ「claude.ai からダウンロードしたスキル」）

## 7. 書いてはいけないこと・注意

- **「8つのコツを試した」とは書かない**：写す元を読む前から運用していた決まりが、8つに当たる。「試した」「検証した」ではなく「ブログ運用の手順書で使っている」「当てはめると」
- ⑥は「テストのファイルは持っていない」と書く（作らない）
- 「スキルにすれば必ず動く」と書かない。「できる」（公式の機能）と「私はこうしている」（CLAUDE.md中心・スキルは一部）を分ける
- ファイル名・行数・日付・記事番号を本文に出さない（`constraints.py`「一般的な問いに制作の記録を出さない」）。「記事の手順書」「Xの手順書」「文字数を数えるプログラム」と中身で言う。`CLAUDE.md`・`SKILL.md`は一般の用語なので出してよい
- 本文に半端な実数を書かない（SKILL.mdの行数など）
- 元の記事の文章・表・図は写さない。8つのコツの整理を使うので、本文（H2-3の頭）で元の記事を紹介してリンクする
- 英語のリンクは貼らない（agentskills.ioは貼らない）
