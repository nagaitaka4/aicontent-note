# 骨格

```
# Dynamic Workflowsで記事チェックを10体に任せた

→ H1直下リード（3文・150字以内／1文目40字以内）
→ 1文目でKWに直接答える：Dynamic WorkflowsはAIを何体も同時に動かすClaude Codeの機能である、と言い切る
→ 2〜3文目で「記事チェックの10項目を10体に1つずつ渡した。人が見つけた7件のうち当たったのは1件だった」まで出す
→ ⚠️ 結論を隠さない。検索で来た人が離脱しない位置に数字を置く

## Dynamic Workflowsは、AIを何体も同時に動かす機能

→ 非エンジニア向けの説明はここだけ。短く終わらせる（解説記事にしないため）
→ 1体が順番に見るのと、10体が同時に見るのとの違い。バックグラウンドで動くので、待っている間もチャットは使える
→ 全有料プランで使える／Proは`/config`の「Dynamic workflows」行でオンにする
→ 出典：https://code.claude.com/docs/en/workflows （2026-09-09に原文確認済み。執筆時に再確認する）
→ 【ポイント】ブロック1つ。表は置かない
→ 内部リンク：用語が分からない読者の受け皿として[Claude Code初心者が最初に理解すべき用語まとめ]

## 記事チェックの10項目を、10体に1つずつ渡した

→ 何を試したかを書く。このブログには機械で判定できないチェックが10項目あり、いまは人が1つずつ目で見ている
→ 10項目の例を3つだけ出す（事実以外を書いていないか／同じ内容を別の言い回しで2回書いていないか／体験談が3割を超えていないか）。10個並べない
→ 対象は自分の記事の修正前バージョン。**あとから11点の指摘を受けて直した版なので、答え合わせができる**
→ 表①：実測（10体／8分12秒／545,566トークン／22件検出／エラー0）
→ ⚠️ トークン数は「多い」と書くだけにする。料金換算はしない（プランによって意味が変わるため）

## 人が見つけた7件のうち、AIが言い当てたのは1件だった

→ この記事の芯。数字を先に出す
→ なぜ分母が11ではなく7なのかを説明する（11点のうち3点は人側の勘違いで直す必要がなかった／1点は画像の話で本文ではない）
→ 表②：7件の結果（当てた1件・文は当てたが理由が違う3件・届かなかった3件）
→ ⚠️ AIが3点の勘違いを1件も出さなかったことをここで書く。「無いものを見つけたことにしなかった」

## 「文は見つかるが、理由が違う」が3件あった

→ 位置は7件中4件まで届いていた。当たらなかったのは理由のほう
→ 具体例を1つだけ深く出す：noindexの一文について、AIは「同じことを2回書いている」、人は「404が1件減っていて数が合わない」
→ ⚠️ ここが読者への持ち帰り。**AIの指摘は「どこを見ろ」として読むと当たる。「なぜ悪いか」は自分で決める**
→ 表は置かない。前後を地の文と例で読ませる

## AIだけが見つけたものが1件あった

→ 公開済みの記事に残っていた矛盾。人が同じ種類の間違いを3箇所直して、4箇所目を見落としていた
→ 該当箇所を実際に出す（「17本と9本の記事が未登録」が、同じ記事の「未登録は1本」と食い違う）
→ ⚠️ 事実として書けるのはここまで。「AIのほうが優秀」とは書かない（メディアの根幹思想）
→ 内部リンク：ここでno.64を振り返る。「確認は人に残る、と1週間前に書いた」という振り返り文の中に埋め込む

## 任せ方を変えると、拾えるものが変わる

→ 実務の持ち帰り3点。読者が今日できることに落とす
→ ①10項目をまとめて渡さず、1項目ずつ分けて渡す（分けたから項目ごとに判定が出た）
→ ②指摘は「場所」として読む。理由は自分で決める
→ ③確かめる材料が同じ場所にあるかで結果が変わる。今回AIは8月10日の記録を見に行こうとして、その記録がこの環境に無く、確かめられなかった
→ 結び：置き換えではなく、目の細かさが違う網が2枚になった。どちらか一方では抜ける
→ ⚠️ 「自動化率」の話に寄せない。no.64の結論の言い直しになる
```
