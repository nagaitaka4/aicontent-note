   ・△＝文にはたどり着いたが、理由が違った
   ・✗＝たどり着かなかった
→ **△を成功に数えない理由を1文で書く。**理由が違えば、その指摘どおりに直しても記事は直らないから

## 渡していない観点は、当然拾えなかった

→ ⚠️【第3稿】**冒頭に、この章が誰にでも効くことを1文で置く。**
   「並列で10体動かさなくても、AIに何かを見てもらう人には同じことが起きます」
→ 【指摘②】分母の話。ここを飛ばすと以降の数字が全部あやしくなる
→ 人が直したのは7点。**そのうち2点は、渡した10項目のどれにも当たらなかった**
→ 2点の中身：どちらもGoogleの公式ドキュメントとの突き合わせ（表現が公式と違う／仕様の理解が違う）
→ 10項目の01は「事実以外を書いていないか（実体験のないことを『試みた』と書いていないか）」で、**公式との照合は頼んでいない**
→ ⚠️ ここが読者への持ち帰り①：**採点する前に、何を渡したかを見る。**渡していないものが拾えないのは道具のせいではない
→ 表は置かない。地の文と例で読ませる
→ **分母を5に確定させてから次のH2へ渡す**

## 5点のうち、理由まで当てたのは1点だった

→ この記事の芯。数字を先に出す
→ ⚠️【第3稿】**数字のあとに、この章が誰にでも効くことを1文で置く。**
   「AIにレビューを頼んだことがある人なら、この分かれ方に見覚えがあると思います」
→ 表②：5点の結果（○1・△3・✗1）と、それぞれを検出したエージェント名
→ ✗だった1点（A-6）の補足：3箇所とも拾えていない。ただし**同じ種類の欠陥の4箇所目**は拾った（次のH2へつなぐ）
→ △3件のうち1件を深く出す：noindexの一文について、AIは「同じことを2回書いている」、人は「404が1件減っていて数が合わない」
→ ⚠️【指摘⑦】ここで一般化しない。**「今回の3件では、AIの指摘は『どこを見ろ』としては当たっていた」**と、件数を必ず添える
→ Dynamic Workflows全般・AI記事チェック全般の性質としては書かない

## AIだけが見つけたものが1件あった

→ 公開済みの記事に残っていた矛盾。人が同じ種類の間違いを3箇所直して、4箇所目を見落としていた
→ 該当箇所を実際に出す（「17本と9本の記事が未登録」が、同じ記事の「未登録は1本」と食い違う）
→ ⚠️【指摘⑨】**なぜこの1件だけを採用したのかを、ここで必ず書く。**基準は「**本文の外にある記録で、どちらが正しいか決まるか**」
   ・この1件は記事内の2文が食い違い、**別の場所に残していた運用の記録**で正解が決まった
   ・他は「重複か」「断定が強いか」という判断の問題で、記録を見ても真偽が決まらない
→ ⚠️【第4稿】**「外部の一次記録」「一次情報」と書かない。**自分の運用記録であって第三者資料ではない
→ ⚠️ 事実として書けるのはここまで。「AIのほうが優秀」とは書かない（メディアの根幹思想）
→ ⚠️ **「いまも公開されている」とは書かない。**2026-08-14の公開から26日間残り、2026-09-09に直した

## 22件のうち、17件は正しいかどうかを確かめていない

→ 【指摘③④】帳尻を読者に渡す。ここが無いと「都合の良い1件を選んだ」に見える

→ 【アラート】ブロック：**確認していない指摘を「AIが見つけた件数」として数えない**

## 今回言えること、まだ言えないこと
