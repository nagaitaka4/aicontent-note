# Gitとは？AI時代の『変更履歴管理』を非エンジニア向けに解説

【GEO直接回答（H2より前に配置）】
Gitは、ファイルの変更履歴を記録・管理するシステムです。
「いつ・何を・なぜ変えたか」を残すことで、AIとの業務でも変更を追跡・巻き戻せる状態を作れます。

---

## Gitがなければどうなるか
→ 「変更管理の問題」を先に体感させる。読者が「あるある」と感じるところから入る

### ファイル名で管理する方法の限界
→ _v2・_最終・_最終2 という命名の問題。差分が追えない・理由が残らない

### AIに変更を頼み続けると起きること
→ AIは過去の変更経緯を知らない。毎回ゼロから指示が必要になる現実

---

## Gitとは何か
→ 概念の核を説明。エンジニア向けでなく「非エンジニアが業務に使える理解」に絞る

### 変更をスナップショットとして保存する仕組み
→ 「上書きではなく記録の積み重ね」という発想の転換

### 「いつ・何を・なぜ変えたか」が残る
→ コミットメッセージの意味。記録に意図を添えることの実務的な価値

---

## 非エンジニアがGitを知っておくべき理由
→ 「自分には関係ない」と思いがちな読者への橋渡し。AIとの協業が前提になっている現実を示す

### AIはGitを前提として動く
→ Claude Codeなどが git init・git commit を前提に設計されている事実

### ルールファイル・指示書の変更を追跡できる
→ AIへの指示（CLAUDE.mdなど）が変化していくことの実態。変更履歴がないと何が起きるか

---

## Gitの基本概念を日常の言葉に置き換える
→ 技術用語を最小限に。日常のアナロジーで理解できるレベルに落とす

### リポジトリ：プロジェクトごとの保管庫
→ 「フォルダ＋その変更履歴がセットになった場所」

### コミット：変更の記録単位
→ 「保存ではなく、意図を持った記録」

### ブランチ：試行錯誤を本流に影響させない分岐
→ 「別ノートで試してOKなら清書に移す」感覚

---

## AIと働く上でGitが機能する場面
→ 抽象論で終わらせず「これが使える瞬間」を具体的に示す。実務視点（GEO対応）

### ルールファイルを更新したとき
→ AIへの指示を変えた理由・日付が残る。「なぜ変えたか」が追えるようになる

### 失敗したら戻せる
→ AIが出した変更が意図と違ったとき、前のバージョンに即戻せる。実験コストが下がる
