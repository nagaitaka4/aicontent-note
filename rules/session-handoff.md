# セッション引き継ぎ・更新内容

終了/開始トリガーの検知条件はCLAUDE.md本体を参照。ここでは`operations/session-handoff.md`を更新する際に必ず含める項目を定める。

## 必ず記載する項目

- **次のセッションでまず行うこと**：確認不要で即実行できる具体的な1アクション（例：「S-13の構成案を作成して提示する」）
- **進行中の作業**：途中で止まっているタスクと現在地
- **直近の判断・保留事項**：決定済みのことと、まだ決まっていないこと
- **最終更新日**

## X編集部の状態（2026-08-24追加・省略禁止）

**「前回のX編集部の続きをお願いします」で即座に動ける状態にする。**引き継ぎにX編集部が1行も無いと、新セッションはキューを一から読み直すことになる。以下を必ず1ブロックで書く。

| 項目 | 書く内容 |
|---|---|
| 投稿TOP1 | ID・軸・ランク・**鮮度期限があれば日付**・そのまま出せるか（要改稿なら何を直すか） |
| 確定枠 | 日付が決まっている投稿（予約枠・旬ネタの期限日） |
| キュー在庫 | 本数／★★★★★の数／軸②比率／取材の要否 |
| リプライの除外状況 | **14日ルールで外れている相手と解除日**（`rules/x-post-flow.md`「除外台帳」）。**リプライ先そのものは書かない**——投稿日にリサーチして決めるため |
| 直近の投稿 | 最後に出したID・日付・軸（同軸連続を避けるため） |
| リサーチ連携の状態 | デイリー／フル版が最後に投入した下書きと、未処理の旬ネタの有無 |

**引き継ぎに書くのは「状態」であって「順位の正」ではない。**順位・下書き本文の正は`knowledge/x/queue.md`。引き継ぎはそこへの入口として書く。

## 書いてはいけないもの

**タスクの優先順位リスト（TOP6）はここに書かない。**`~/Documents/GitHub/tasks/README.md`のみで管理する（`rules/task-management.md`参照）。
