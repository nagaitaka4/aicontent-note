# X投稿制作フロー・ルール（X編集部システム）

X投稿を提案・作成するすべての作業でこのファイルを参照する。

---

## X編集部の構造

このアカウントの投稿は「CCが考えたネタを出す」のではなく、**「ユーザーの体験を取材して価値を引き出す」** 編集部として動く。

```
[取材] → [素材ストック] → [ネタ選定] → [制作] → [公開] → [振り返り]
          ideas.md                         published.md更新
             ↑
   月・金リサーチ自動連携（軸②）
```

**CCの役割は編集者：**
- 取材者として、ユーザーの体験から価値を掘り起こす
- 編集者として、素材から「一番強い断片」を選ぶ
- ライターとして、選んだ断片を140文字に仕上げる

**ユーザーにしか書けないものが素材の起点：**
強い投稿はCCが考えたネタから生まれない。ユーザーが実際にやったこと・気づいたこと・驚いたことから生まれる。

## 0. 着手前に必ず読むこと（省略禁止）

1. `knowledge/x/published.md`：直近5件のビュートレンドと高ビューパターンを確認
2. `knowledge/x/ideas.md`：現在の素材ストックと取材待ちリストを確認
3. `sns/posts-stock.md` の冒頭（運用ルール・ポジション・投稿4軸・投稿済み一覧）：提案テーマの重複チェック

## 1. 取材フロー（軸①・気づき型の起点）

インタビューした内容は `knowledge/x/interviews.md` に記録する。断片の解像度・取材日・ステータスが残ることで、次のセッションでも続きから動ける。

### CCがインタビューするタイミング

以下のどれかに該当したら、CCはユーザーに1〜3問インタビューして `knowledge/x/ideas.md` に記録する。

- ユーザーが「面白い」「気づいた」「変わった」「驚いた」を含む発言をした
- 日常作業の中で「これは一次情報になる」とCCが判断した
- 記事制作中にユーザーが体験ベースのコメントをした

### インタビューの作法

CCは以下の問いで断片の解像度を上げる。1〜3問で終わらせる（掘りすぎない）。

```
① 「それ、具体的にどのくらい変わりましたか？（時間・回数・比率）」
② 「それが変わる前は、どういう状態でしたか？」
③ 「一番驚いたのはどの部分ですか？」
```

**判断：取材した断片がホームラン候補か？**

| 判断基準 | Yes → | No → |
|---|---|---|
| 「永井さんにしか書けない」か | ideas.mdにストック | 没（記録せず） |
| 数字・変化・逆説がある | 強い素材として記録 | インタビューを深める or 没 |

## 2. リサーチ連携フロー（軸②・AI動向型の起点）

月・金の定期リサーチ（research/配下）終了後、CCは以下を実行する。

1. `research/trends.md`・`research/ai-tools.md`・`research/seo-insights.md` をReadして更新内容を確認
2. X向きネタ判定（下記基準）
3. 該当ネタを `knowledge/x/ideas.md` の「リサーチ由来」に追記

**X向きの判断基準（軸②用）：**

| X向き（追記） | X向きでない（追記しない） |
|---|---|
| タイムリー（今週中に出せる） | 1週間以上前の情報 |
| 実務に落とせる（「自分の場合は〜」がある） | ニュース紹介で終わる |
| 「知らなかった」「すごい」が動く | 情報として重要だがスクロールを止めない |

**旬ネタの鮮度：**
- AI動向は発表から3日以内が最高ビュー帯。リサーチ当日か翌日に出すのが原則
- 3日を過ぎたら「実務への影響の振り返り」に切り口を変えて出す

## 3. ネタ選定フロー（編集会議）

### 「次の投稿」を決めるとき

1. `knowledge/x/ideas.md` の素材ストックを全件確認
2. `knowledge/x/published.md` の高ビューパターンを参照して選定
3. `sns/posts-stock.md` の投稿済み一覧で重複チェック・開き方の被りを確認

**選定の優先順位：**

| 優先 | 素材 | 条件 |
|---|---|---|
| 1 | 旬のリサーチ由来（軸②） | 発表から3日以内 |
| 2 | 取材済み断片（軸①）でホームラン候補 | 数字・変化・逆説がある |
| 3 | 記事由来リンク型（軸③） | X向き判定済みで投稿タイミングが来ている |
| 4 | 取材済み断片（軸①）で普通強度 | 直近5件と開き方が被っていない |

**投稿比率目標：**
軸①50% / 軸②30% / 軸③15% / 軸④5%

**NG選定：**
- 素材に「断片の核」がない状態でテーマだけ決まっている
- ideas.mdにない素材を「なんとなく」で提案する
- 弱いと分かっていて「一応これで」と出す

## 4. 制作ルール（執筆）

### 最重要ルール

```
説明を書くな。変化を書け。
知識を書くな。体験を書け。
AIを説明するな。AIで自分がどう変わったかを書け。
記事を要約するな。記事を読む理由を書け。
気づきだけで終わるな。断片を見せろ。
```

**品質基準：90点未満は出さない。**  
弱いと判断したらテーマから見直し、別テーマを提案する。

### 必ず入れるもの

- Before→After
- 数字（時間・本数・割合）
- 実体験・実際の感情（迷い・驚き・気づき）
- **実務の断片**（実際に使っているREADME・ルール・設定の一部）← 再現性の源泉

### NG

- 説明だけの投稿（「Gitとは〜」「Claudeとは〜」）
- 一般論（「AIは便利です」「Gitはおすすめです」）
- まとめで終わる（「だから重要です」「役立ちます」）
- 記事の要約
- 気づきだけ・ニュースだけで終わる

### 出力前チェック（7項目・省略禁止）

① スクロールを止める1文目か  
② 説明ではなく体験か  
③ 具体的か（数字・固有名詞・状況）  
④ 一般論になっていないか  
⑤ 「自分はこうだった」になっているか  
⑥ 140文字以内か  
⑦ 最後に余韻があるか

### リンク型を作る前の判断（省略禁止）

記事を公開したからといって、必ずXで紹介する必要はない。

**X向き（作る）：**
- 数字がある（出品時間が半分・8時間→4時間）
- あるある・共感フックがある（最新版どれ？）
- 「知らなかった」「すごい」「自分もやりたい」のどれかが動く

**SEO向き（Xでは触れない）：**
- 検索クエリに刺さるが、スクロールを止める力がない
- フックを無理に作っても解消できない

### 良い投稿の例

#### 例①（軸①・結論→体験）
```
WEBライティング副業、一度やめます。

8応募、2テスト、0契約。手取り435円。

時給換算より本当にきつかったのは、
時間を使って「積み上がる感」が全くなかったこと。

やってみて、出した結論です。
```
→ 結論先出し。数字。感情の核が「積み上がらない」という具体的な絶望感。

#### 例②（軸①・逆説）
```
Claude Codeって、
一番すごいのはAIじゃないかもしれません。

README.mdを置くだけで、
毎回説明していた前提が共有される。

「AIと会話する」より
「環境を作る」方が大事なんだと感じました。
```
→ 「一番すごいのはAIじゃない」という逆張りで開く。

#### 例③（軸①・数字×変化）
```
AIで記事を作りはじめて44本。
公開までの時間は1本8時間→4〜5時間になりました。

「ここはAI」「ここは自分」が見えるようになって、
迷う時間はかなり減りました。

でも、次の1時間を縮めるのが一番難しそうです。
```
→ 数字→抽象化。「気がします」で断定しない。

#### 例④（軸②・AI動向＋実務落とし）
```
Gemini CLIが有料化、OpenCodeが急成長、Cursorが刷新。

正直、どれも使ったことがありません。

それでも今のところ困っていないのは、
Claude Codeで作業設計が完結しているから。

「何を使うか」より「どう設計するか」が先だと思っています。
```
→ 話題に乗りながら自分の立場を明確に。

## 5. 振り返りフロー

### 投稿後1週間以内に実施

1. X（x.com/aicontent_note）で当該投稿のビュー数を確認
2. `knowledge/x/published.md` の対応行にビュー・いいね・RTを記録
3. 「高ビュー投稿の共通パターン」を必要に応じて更新

### ビューが10未満だった場合

没にせず、「何が弱かったか」を振り返る。

```
□ 断片の核があったか
□ 開き方（1文目）がスクロールを止める力があったか
□ 同パターンの投稿が直近5件で被っていなかったか
□ タイムリー性があったか（AI動向型の場合）
```

この振り返りは次の選定に直接使う。

## 7. セッショントリガー

### 「次の投稿を作ってください」

CCが以下を実行して1本提示する。

1. `knowledge/x/ideas.md` を読んで素材を確認（取材済みか・旬ネタか）
2. `knowledge/x/published.md` を読んで高ビューパターンと直近ビュートレンドを確認
3. `sns/posts-stock.md` を読んで重複と開き方の被りを確認
4. 以下のいずれかで提示：
   - **断片が明確（リンク型・取材済み気づき型）** → CCが140文字で起こして提示
   - **断片が曖昧（気づき型）** → インタビュー1〜3問してから制作
   - **旬ネタ（AI動向型・ideas.mdにあり）** → CCが投稿文を起こして提示
5. 90点未満と判断したら別素材を選ぶ

### 「取材してください」（または日常作業中に体験発言があった場合）

CCが以下を実行する。

1. インタビュー1〜3問（具体的数字・Before・驚きを掘り起こす）
2. 得た断片を `knowledge/x/interviews.md` に記録（問い・答え・抽出した核・ステータス）
3. 投稿化できる強度があれば `knowledge/x/ideas.md`「取材素材」にも追記
4. 「投稿文を作りますか？それとも次回のストックにしますか？」と確認

### 「投稿完了しました」（または投稿内容を貼った場合）

CCが以下をすべて実行する（確認不要・自動実行）。

1. `sns/posts-stock.md` の投稿済み一覧に追記（全文アーカイブも必須）
2. `knowledge/x/ideas.md` の該当素材を削除
3. `knowledge/x/published.md` に新規行を追記（冒頭・軸・日付。ビューは1週間後に補完）
4. `~/Documents/GitHub/tasks/README.md` のX継続投稿セクションを更新
5. 両リポジトリをコミット

### 「ビューを確認してきました」

CCが以下を実行する。

1. `knowledge/x/published.md` を更新（ビュー・いいね・RTを記録）
2. 高ビューパターンに変化があれば冒頭の「高ビュー投稿の共通パターン」を更新
3. 「振り返りメモ」に学びを追記

## 8. 最終確認の問い

投稿を書き終えたら必ず自問する。

> この投稿は「へぇ」で終わるか？
> それとも「この人、実際にAIで仕事してるんだ」と思われるか。

前者なら全面的に書き直す。
