# X投稿制作フロー・ルール

CLAUDE.mdのX投稿ルールと、`sns/posts-stock.md`に既に埋め込まれていた運用実態、これまでCCのメモリにのみ存在していた関連ルールを統合したもの。X投稿を提案・作成するすべての作業でこのファイルを参照する。

## 0. 提案前に必ず読むこと（省略禁止）

`sns/posts-stock.md`は投稿済み一覧の表だけでなく、**冒頭の「運用ルール」「Xのポジション」「戦略メモ」「投稿4軸と優先順位」を毎回読んでから**提案する。表だけを見て過去の流れを踏まえずに提案しない。

- 提案する投稿番号のステータスが`draft`であること（`posted`/`archived`でないこと）
- 提案する内容の書き出し・テーマが、投稿済み（posted）の内容と重複していないこと
- 現在の軸別比率目標（軸①50%／軸②30%／軸③15%／軸④5%）と、直近の投稿がどの軸に偏っているかを踏まえる
- 気づき型とリンク型の同記事ペアは3〜5本間隔を空ける
- 戦略メモの直近の方針転換（例：副業検証シリーズは完結・運用論系は保留）を反映する

この確認なしに投稿を提案しない。

## 1. X投稿のポジション（最重要）

- Xは記事への「カジュアルな入口」。記事は読んでもらう場所
- X投稿は告知・宣伝にしない。読んだ人が「あるある」「気になる」と感じる内容にする
- 気づき型・実況型・リンク型すべて、トーンはカジュアル・ラフ・本音ベース
- リンク型も「記事書きました」ではなく、読みたくなる入口として設計する
- ターゲットは非エンジニアに絞る。「AIで楽になった」ではなく「3時間→1時間半」のような具体的な変化を出す
- **AIと人は対等な目線で発信する**（メディアの根幹思想）：「AIはこういうものだ」という断定を避け、「気がします」「思います」など個人の観察として出す

## 2. 制作手順

1. **テーマ決定**：CCが投稿済み一覧をすべて把握した上でテーマ候補を1〜2案提示する（推奨投稿順・軸比率に従う）
2. **インタビュー要否の判断**
   - リンク型：元記事が既にあるためインタビュー不要。CCが本文を作成する
   - 実験ログ・運用論・AIニュース：CCが書けるものはそのまま作成。実体験や判断が必要な内容のみ、その部分だけCCがインタビューする
   - 上記以外で気づき型・実況型など実体験がメインの投稿：インタビュー必要。実体験・本音・具体的なエピソードをCCから質問し、回答を素材にする
3. **投稿文作成 → ユーザー確認 → 投稿**
4. 投稿後、`sns/posts-stock.md`の投稿済み一覧に追記し、**下書きストックから該当項目を削除する**（削除漏れが起きやすいので必ず確認する）

## 3. 品質基準（提示前の自己チェック・省略禁止）

初稿からそのまま投稿できる品質で出す。提示前にCC自身で以下を確認する。

- ターゲット（非エンジニア）視点で意味が通るか
- 事実関係が正確か（数字・固有名詞の確認含む）
- 論理・話の流れが破綻していないか
- 核となる一文が明確か
- 文字数がXの投稿として適切か
- **同じ言い回し・結論パターンを過去の投稿と繰り返していないか**（rules/article-flow.md 0章と共通の原則）

## 4. タスクリストとの連動（省略禁止・確認不要で即実行）

`sns/posts-stock.md`のposted更新と同時に、必ず`~/Documents/GitHub/tasks/README.md`の以下2箇所を更新する。

1. TOP5の補足欄：「○○番〜順次投稿」の番号を次の番号に更新
2. X継続投稿セクション：「順次投稿（○○番〜）」と「投稿済み一覧」を最新状態に更新

## 5. 割り込みルール

AIニュースの旬ネタが来たら、推奨投稿順を崩してでも随時割り込んでよい。ただしニュースで終わらせず、運用視点に変換して出す（軸②の書き方基準に従う）。
